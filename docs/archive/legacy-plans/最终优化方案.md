# 最终优化方案（导出质量优先）

## 一、优化背景
当前导出链路存在三类问题：
- 质量波动：超高 DPI 虽清晰但易触发内存峰值，导致后续被动降采样，文字锐度不稳定
- 稳定性风险：Office COM 对中文路径、窗口控制敏感，易出现导出失败
- 速度压力：高 DPI + 多步 I/O 会拉长整体导出时间

在质量优先的前提下，需要同时保证稳定性，并尽量优化速度。

## 二、优化目标（优先级递减）
1) 导出质量高：文字边缘清晰、版式一致
2) 运行稳定：不因路径/COM/内存峰值崩溃
3) 运行速度不慢：在保证清晰度前提下尽量提升

## 三、最终方案（可落地且 AI 可实现）
### 1) 统一 PDF 中间态
统一流程：Word / PPT / PDF -> PDF -> PNG  
- Word/PPT 先转 PDF，保证固定版式
- PDF 统一使用 PDFium 渲染，质量可控、流程一致

### 2) 清晰度策略：目标像素 + DPI 约束
采用“目标像素尺寸优先”而不是“盲目提升 DPI”：
- 1x：短边 2400–2600px（默认）
- 1.5x：短边 3000–3400px
- 2x：短边 3600–4000px
- 3x：短边 4500–5000px（极少数场景）

优势：
- 清晰度稳定、可预测
- 避免 900 DPI 带来的内存峰值

### 3) 内存峰值控制
渲染前计算像素量，设置上限（例如 60MP）：
- 超出阈值自动降低渲染 scale
- 避免崩溃与系统卡顿

### 4) 稳定性增强：路径安全化
COM 处理前统一复制到 ASCII 临时路径：
- 避免中文路径导致 Word COM 打开失败
- 输出仍回写到用户指定目录

### 5) 输出策略（不做体积限制）
保持 PNG 输出（质量优先），体积不限制：
1) 高质量渲染
2) 3:4 裁剪（可选）
3) PNG 无损编码（默认参数）

## 四、落地规划
### 阶段 1：核心质量与稳定性改造
- PPT 改为 “PPT -> PDF -> PNG”
- Word/PPT COM 统一 ASCII 临时路径处理
- 导出阶段提示：Word 转 PDF / PPT 转 PDF / PDF 渲染 / 图片后处理

### 阶段 2：渲染策略重构
- 引入“目标像素尺寸”策略
- 限制渲染像素上限（60MP）

### 阶段 3：性能细节优化
- PDF 页渲染支持受控并发（如 CPU 核心数/2）
- 渲染完成即释放内存 buffer

## 五、验收标准
- 文字清晰，无发虚、锯齿明显问题
- 单张图片体积不限制
- 文档批量导出过程中无 COM 崩溃
- 导出阶段提示准确，能定位到当前页

## 六、说明与边界
不引入 MuPDF/Poppler CLI 的原因：
- 依赖复杂、打包风险高
- 对稳定性影响不可控
- 不符合“AI 可稳定实现”的要求

如未来需要极致锐度，可评估引擎升级，但作为第二阶段可选项。
