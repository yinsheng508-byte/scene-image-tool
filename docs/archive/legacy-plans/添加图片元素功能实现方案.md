# 百变排版拼图 — 添加图片（装饰图片）元素功能实现方案

## 一、需求概述

在百变排版拼图中新增"装饰图片"元素类型，和文字元素并列，支持：
- 添加图片到画布（单选，一次一张）
- 放大、缩小（始终等比缩放）、旋转
- 右键复制、删除
- 与文字元素按添加顺序混排渲染（先添加的在下层），不支持调整层级
- 预览和导出均支持渲染装饰图片

### 布局调整
- "文字操作"区域 → 重命名为"元素操作"
- "元素操作"区域新增"添加图片"和"清空图片"按钮
- "坑位操作"中的"添加图片" → 重命名为"添加图片坑位"

### 明确排除
- 不支持调整层级（严格按添加顺序）
- 不支持对齐/分布操作
- 不支持双击编辑（无编辑态）
- 不需要属性面板（无字体、颜色等样式配置）
- 不需要裁剪功能
- 不允许自由拉伸（始终等比）

## 三、资源管理 — 图片文件复制

### 3.1 主进程新增 IPC — `main.js`

参照 `puzzle:copyBackground` 的实现模式，新增：

**`puzzle:copySticker`** IPC handler：
- 在 `getPuzzleDataDir()` 下创建 `stickers/` 子目录

- 与 `puzzle:loadBackground` 类似，将相对路径转为绝对路径后返回 base64 或文件路径

新增辅助函数：
```javascript
function getPuzzleStickerDir() {
  return path.join(getPuzzleDataDir(), "stickers");
}
```

`ensurePuzzleDirs()` 扩展为同时创建 `stickers/` 目录。

### 3.2 前端加载图片

图片加载复用已有的图片加载逻辑（用于加载坑位图片），需要确保它支持：
1. 绝对路径（本地文件）
2. 基于 `getPuzzleDataDir()` 的相对路径解析

如果现有逻辑只支持绝对路径，需在加载时通过 IPC 把相对路径解析为绝对路径（或新增统一的路径解析方法）。

## 五、核心逻辑实现 — `index.js`

### 5.1 添加图片处理

```
handleAddImageElement():
  1. 调用 window.appApi.openImageFile() 选择图片（单选）
  2. 调用 puzzle:copySticker IPC 复制到专用目录，获取 relativePath
  3. 用 loadImage() 获取图片宽高
  4. 创建 image 元素，宽高按画布尺寸等比缩放（若超出画布）
  5. 居中放置，aspectRatio = width/height
  6. pushUndoState()
  7. puzzle.images.push(image)
  8. 设置选中态：selectedImageIds = [image.id], 清空其他选中
  9. saveStateToStorage() + scheduleRender()
```

### 5.2 清空图片处理

```
handleClearImageElements():
  1. confirm("确定清空当前拼图的所有图片元素吗？")
  2. pushUndoState()
  3. puzzle.images = []
  4. 清空 selectedImageIds
  5. saveStateToStorage() + scheduleRender()
```

### 5.3 选中态管理

三种选中态互斥（同一时间只能选中一种类型）：
- `selectedSlotIds` — 坑位
- `selectedTextIds` — 文字
- `selectedImageIds` — 图片

选中图片时，清空 text 和 slot 选中；反之亦然。

`clearSelections()` 增加 `AppState.selectedImageIds = []`。

### 5.4 属性面板更新

`updatePropertiesPanel()` 中：
- 选中图片时：不显示坑位属性面板，不显示文字属性面板
- 可选：显示一个简化的信息提示（如"已选中 N 张图片"），或者不显示任何属性面板

### 5.5 复制/删除图片

```
handleCopyImage():
  clipboardImages = selectedImageIds 对应的 image 对象深拷贝（偏移 +20px）

handlePasteImage():
  clipboardImages 中每个元素 → 新 id + 新 createdAt → push 到 puzzle.images

handleDeleteImage():
  pushUndoState()
  从 puzzle.images 中过滤掉 selectedImageIds 对应的元素
  清空 selectedImageIds
```

### 5.6 键盘快捷键扩展 — `handleKeyDown()`

优先级调整为：image → text → slot

```
Delete: 优先删除图片 → 文字 → 坑位
Ctrl+C: 优先复制图片 → 文字 → 坑位
Ctrl+V: 根据 clipboard 内容判断粘贴类型
Ctrl+A: 优先全选图片 → 文字 → 坑位（或根据当前有哪种选中来决定）
```

### 5.7 右键菜单扩展 — `handleSlotContextMenu()`

命中检测顺序调整：
1. 先检测图片元素 → `contextMenuTarget = "image"`
2. 再检测文字 → `contextMenuTarget = "text"`
3. 最后检测坑位 → `contextMenuTarget = "slot"`

`handleSlotMenuCopy()` 和 `handleSlotMenuDelete()` 增加 `"image"` 分支。

菜单文案动态设置：
- image: "复制图片" / "删除图片"
- text: "复制文字" / "删除文字"
- slot: "复制坑位" / "删除坑位"

## 六、渲染管线改造

### 6.1 编辑态渲染 — `renderEditor()`（index.js）

**当前顺序**：背景 → 坑位 → 文字 → 选中手柄

**改造后顺序**：
```
1. 背景（颜色或图片）
2. 画布边框
3. 坑位层 drawSlots()              ← 不变，坑位始终在最底层
4. 元素层（文字 + 图片混排）        ← 改造点
   - 合并 puzzle.texts 和 puzzle.images
   - 按 createdAt 升序排列（小的先画，在下层）
   - 遍历：type==="text" → drawText()，type==="image" → drawImageElement()
5. 选中态手柄
   - 坑位 handles（不变）
   - 坑位组 handles（不变）
   - 文字选中框 + handles（不变）
   - 图片选中框 + handles（新增）
   - 文字组 handles（不变）
6. 选区覆盖层（不变）
```

### 6.2 图片元素绘制函数 — 新增 `drawImageElement()`

```
drawImageElement(ctx, imageObj, imageCache):
  1. 从缓存获取 Image 对象
  2. 若未加载则触发异步加载 + scheduleRender()
  3. ctx.save()
  4. 计算中心点：cx = x + width/2, cy = y + height/2
  5. ctx.translate(cx, cy)
  6. ctx.rotate(rotation * Math.PI / 180)
  7. ctx.drawImage(img, -width/2, -height/2, width, height)
  8. ctx.restore()
```

### 6.3 图片选中框绘制 — 新增 `drawImageSelection()`

与 `drawTextSelection()` 类似：
- 蓝色虚线边框
- 4 个角 handle（等比缩放，避免边 handle 造成“可拉伸”的误解）
- 旋转手柄（圆形，位于顶部上方 20px）

建议复用 `drawTextSelection()` 的绘制逻辑，传入图片的 bounding box。

## 七、交互实现 — 新增 `image-editor.js`

### 7.1 模块结构

参照 `text-editor.js` 的结构，新建 `image-editor.js`，但简化版：

**导出函数**：`createImageEditor(options)` 返回对象：
```javascript
{
  mousedown(worldPoint, event),
  mousemove(worldPoint, event),
  mouseup(worldPoint, event),
  canEdit(),
  getImageAtPoint(worldPoint),    // 命中检测
  getSelectedImageBounds(),       // 获取选中图片边界
}
```

**回调**：
```javascript
options = {
  getImages(),                    // () => puzzle.images
  getSelectedIds(),               // () => AppState.selectedImageIds
  setSelectedIds(ids),            // 设置选中
  onImagesUpdated({ phase }),     // "start"|"change"|"end"
  isEditable(),                   // 是否可编辑
  scheduleRender()
}
```

### 7.2 核心交互逻辑

**命中检测 `isPointInImage(worldPoint, imageObj)`**：
- 复用 `rotatePoint()` 工具函数
- 将世界坐标反旋转到图片本地坐标系
- 判断是否在 (0,0,width,height) 矩形内

**Handle 检测**：
- 4 个角 handle + 旋转 handle
- 边 handle 可选保留（行为与角 handle 相同，都是等比缩放）

**拖动移动**：
- 记录 dragStart 的 x/y 偏移
- mousemove 时更新 image.x / image.y

**缩放（等比）**：
- 任何 handle 拖动时，计算缩放比例
- 根据 aspectRatio 同时更新 width 和 height
- 锚点为对角 handle 位置（或中心点）

**旋转**：
- 旋转 handle 在图片上方 20px（与文字一致）
- Math.atan2 计算角度差
- 更新 image.rotation

### 7.3 与 index.js 集成

当前交互结构是 **每种编辑器自己绑定 canvas 事件**（`canvas-editor.js` 与 `text-editor.js` 都是直接 addEventListener）。
图片编辑器应采用同样模式：在 `initEditor()` 中创建 `imageEditor`，并让其在处理命中后 `event.stopPropagation()`。
通过 **注册顺序** 实现优先级（建议：image-editor → text-editor → canvas-editor）。

命中检测时图片与文字层级混排，若需要“上层优先”，则在 image-editor 内部按 createdAt 倒序检测图片；文字仍由 text-editor 处理。

## 九、导出生成 — `main.js`

### 9.1 `puzzle:generate` IPC 改造（第 1047-1086 行区域）

当前 composites 构建顺序：
```
坑位图片层 → 文字层（全画布大小的文字 buffer）
```

改造为：
```
坑位图片层 → 元素层（文字 + 图片混合）
```

### 9.2 方案 A：扩展 `createTextLayerBuffer()` 为 `createElementLayerBuffer()`

将函数改名并扩展：在同一个 canvas 上按 createdAt 顺序绘制文字和图片。

```javascript
async function createElementLayerBuffer(task, scale = 1) {
  const texts = Array.isArray(task?.texts) ? task.texts : [];
  const images = Array.isArray(task?.images) ? task.images : [];
  if (!texts.length && !images.length) return null;

  // ... 创建 canvas（同原逻辑）

  // 合并排序
  const elements = [
    ...texts.map(t => ({ ...t, _type: "text" })),
    ...images.map(i => ({ ...i, _type: "image" }))
  ].sort((a, b) => (a.createdAt || 0) - (b.createdAt || 0));

  for (const el of elements) {
    if (el._type === "text") {
      drawText(ctx, el);
    } else {
      // 加载图片文件（绝对路径）
      const imgPath = path.join(getPuzzleDataDir(), el.imagePath);
      const { loadImage } = getCanvasLib();
      const img = await loadImage(imgPath);
      if (img) {
        ctx.save();
        const cx = el.x + el.width / 2;
        const cy = el.y + el.height / 2;
        ctx.translate(cx * scale, cy * scale);
        ctx.rotate(el.rotation * Math.PI / 180);
        ctx.drawImage(img, -el.width * scale / 2, -el.height * scale / 2,
                       el.width * scale, el.height * scale);
        ctx.restore();
      }
    }
  }
  return canvas.toBuffer("image/png");
}
```

注意：此函数中 ctx 已做了 `ctx.scale(safeScale, safeScale)`，所以图片绘制时坐标不需要额外乘以 scale。

### 9.3 `puzzle:generate` 中替换调用

```javascript
// 原来
const textLayer = await createTextLayerBuffer(task, scale);

// 改为
const elementLayer = await createElementLayerBuffer(task, scale);
```

composites 位置不变（left: 0, top: 0 的全画布覆盖层）。

## 十六、关键注意事项

1. **命名区分**：`puzzle.images` 是装饰图片元素数组，`AppState.images` 是导入的坑位素材图片列表，两者完全不同，不要混淆。用 `imageElements` 作为变量名可以更清晰。

2. **createdAt 贯穿**：老数据的 text 对象没有 `createdAt`，需要在加载时补充；同时确保在 clone/undo/模板/导出链路中都保留该字段，避免层级顺序丢失。建议用递增的 `Date.now() + index` 保证顺序。

3. **等比缩放**：仅保留角 handle，拖动时维持 aspectRatio，不允许自由拉伸。缩放逻辑比自由拉伸简单。

4. **图片缓存**：装饰图片的 Image 对象需要缓存，复用已有的图片缓存机制，避免每次渲染都重新加载。

5. **主进程图片加载**：`createElementLayerBuffer()` 在 node-canvas 环境下运行，使用 `getCanvasLib().loadImage()` 加载本地图片，不需要通过 IPC。

6. **旋转绘制**：图片和文字的旋转绘制都是 translate-to-center → rotate → draw-from-center 模式，保持一致。
7. **多选范围**：当前需求未强制多选/框选。若要保持与文字/坑位一致，可复用 `text-editor.js` 的选区逻辑；若不做多选，需要在交互说明中明确“仅单选”。
