# 场景化图片排版工具 - 桌面版与新增功能需求文档（草案）

## 1. 背景与目标
- 现有工具为单页 HTML/JS（`场景化图片排版工具.html`），需转为仅 Windows 的桌面软件。
- 新增两类能力：
  - 批量把 Word/PPT/PDF 导出为图片，支持 1.5x/2x 放大与 3:4 居中裁剪。
  - 从指定图片文件夹中随机上传指定数量图片到飞书多维表格。

## 2. 平台与技术选型（已确认）
- 平台：Windows。
- 桌面框架：Electron（优先复用现有 HTML/JS）。
- 文档转换：
  - Word/PPT：使用已安装的 Microsoft Office COM 接口。
  - PDF：使用 PDFium 渲染。
- 基准分辨率：以“原文档页面像素”为 1x，再乘 1.5x 或 2x。
- 裁剪策略：3:4 居中裁剪。
- 输出格式：PNG。

## 3. 功能需求

### 3.1 文档批量导出为图片
**输入与范围**
- 支持选择“单个文件”或“文件夹”。
- 文件夹模式需递归子文件夹。
- 支持格式：`doc/docx/ppt/pptx/pdf`。
- 其他格式忽略并记录为失败原因。

**导出处理流程（逻辑）**
1. 扫描并收集符合格式的文件。
2. 对每个文件执行转图（优先原生导出，若不支持则走 PDFium）：
   - Word：若支持原生图像导出则直接导出，否则通过 Office COM 生成 PDF，再用 PDFium 渲染为图片。
   - PPT：优先使用 Office COM 原生导出每页为图片；必要时生成 PDF 再用 PDFium 渲染。
   - PDF：用 PDFium 渲染为图片。
3. 渲染后可选进行：
   - 放大：1.5x 或 2x（默认关闭）。
   - 3:4 居中裁剪（默认关闭）。
   - 执行顺序：先放大后裁剪（保证清晰度）。
4. 生成 PNG 输出。

**选项与默认值**
- 放大倍率：可选 1.5x / 2x，默认关闭。
- 3:4 居中裁剪：可选开关，默认关闭。
- 批量模式下显示进度与失败列表。

**输出路径与命名**
- 选择“文件夹”时：用户选择输出目录（建议默认预填为 `原文件夹_导出`）。
  - 保留子文件夹结构，在对应子目录下输出图片。
  - 图片命名：`文档名称-1.png`, `文档名称-2.png`, ...
- 选择“单个文件”时：输出到文件所在目录。
  - 图片命名：`文档名称-1.png`, `文档名称-2.png`, ...

**命名冲突处理**
- 若同名不同扩展或重复导出导致冲突，追加原始扩展后缀：
  - 示例：`A.docx` -> `A-docx-1.png`
  - 若仍冲突，再追加自增序号。

**错误与提示**
- 文件夹内无可处理文件：提示错误并终止。
- 单个文件处理失败：记录失败原因并继续下一个。
- 放大/裁剪导致图像尺寸异常时，提示并跳过该页或降级处理。
- Office 未安装或版本不兼容：提示用户安装或升级 Office。

### 3.2 随机上传图片到飞书多维表格
**输入与范围**
- 用户选择"图片文件夹"（与导出功能独立）。
- 不限制图片扩展名，按可读的图片文件进行判断。
- 若文件夹内无图片则报错并终止。
- 支持用户输入"每行上传图片数 N"，表示每行随机上传 N 张图片。
- N 必须不大于图片文件夹总数。

**随机策略与去重规则**
- 单次上传：每行从图片文件夹中随机选择 N 张，行内不重复。
- 跨行允许重复，每次上传都从完整目录随机，不做跨任务去重。

**上传目标**
- 上传到飞书多维表格的指定字段。
- 用户指定写入的行范围（起始行 + 结束行）。
- 写入映射：每行追加 N 张图片到附件字段（保留原有附件）。
- 总上传图片数 = 行数 × 每行上传数。

**配置依赖（后续接入）**
- 授权码（PersonalBaseToken）+ 多维表格链接（用于解析 `app_token/table_id/view_id`）。
- 目标字段（字段名或 `field_id`）确认，字段类型为附件（`type=17`）。
- 域名选择：国内 `https://base-api.feishu.cn`；海外 `https://base-api.larksuite.com`。

## 4. UI/交互草案
- 新增“导出图片”入口：支持选择文件/文件夹，配置放大倍数与裁剪开关，支持选择输出目录。
- 新增“随机上传飞书”入口：选择图片文件夹、输入上传数量、指定表格字段与行范围。
- 显示处理进度与失败列表，支持导出失败日志。

## 5. 飞书多维表格接入说明（已提供信息）
**授权与域名**
- 使用“飞书多维表格授权码 + 多维表格链接”进行配置。
- 授权码仅能操作 Base 相关开放接口。
- 多维表格在新域名独立部署 Base OpenAPI，接口路径与开放平台一致，但域名不同：
  - `https://base-api.feishu.cn`
  - `https://base-api.larksuite.com`

**能力范围**
- 云文档 - 多维表格（Base）：全部接口。
- 云文档 - 云空间（Drive）：上传素材、下载素材两个接口。

**关键字段获取**
- `app_token`：多维表格 URL 中 `base/` 之后的部分（若路径为 `wiki/`，需用“开发工具”插件获取）。
- `table_id`：多维表格 URL 中对应部分（建议用“开发工具”插件获取）。
- `view_id`：多维表格 URL 中对应部分（建议用“开发工具”插件获取）。

**配置输入与解析规则（补充）**
- 输入项：`授权码（PersonalBaseToken）` + `多维表格链接`。
- 链接解析规则：
  - `app_token`：`/base/{app_token}` 中的 `{app_token}`。
  - `table_id`：Query 参数 `table`。
  - `view_id`：Query 参数 `view`。

**当前测试用链接解析结果（可替换）**
- `app_token`：`GKQkbjNulaF8Qps5urscisO0nGc`
- `table_id`：`tbl4BzbWb1z967qM`
- `view_id`：`vewDUwdhs9`
- 上传字段：`内容页图片`（附件字段，`field_id=fldSd7boGJ`）
- 上传行号：第 2 行（以 `view_id` 视图顺序为准）

**接口使用要点（摘要）**
- 列出记录：`GET /open-apis/bitable/v1/apps/:app_token/tables/:table_id/records`
  - Header：`Authorization: Bearer [PersonalBaseToken]`
  - 支持 `filter/sort/page_size/page_token`。
- 列出字段：`GET /open-apis/bitable/v1/apps/:app_token/tables/:table_id/fields`
- 批量新增/更新记录：
  - `POST .../records/batch_create`
  - `POST .../records/batch_update`
- 批量获取记录：`POST .../records/batch_get`
- 上传素材（图片）：`POST /open-apis/drive/v1/medias/upload_all`
  - 返回 `file_token`，用于写入表格的“附件/图片字段”。
  - 多维表格场景必填 `parent_node`，取 `app_token`。

**接口示例：列出记录（节选）**
- 方法：`GET`
- 域名：`https://base-api.feishu.cn` / `https://base-api.larksuite.com`
- 路径：`/open-apis/bitable/v1/apps/:app_token/tables/:table_id/records`
- Header：`Authorization: Bearer [PersonalBaseToken]`
- Query 示例：`filter/sort/page_size`
- 响应字段：`code/data.items/page_token/has_more`，`record_id` 在 `items` 内返回。

**推荐上传流程（规划）**
1. 使用授权码作为 `PersonalBaseToken`（无需额外换取）。
2. 解析链接得到 `app_token/table_id/view_id`。
3. 列出记录并根据视图顺序映射“行范围 -> record_id”。
4. 通过 Drive 上传图片，拿到 `file_token`。
5. 使用 `batch_update` 将 `file_token` 写入指定字段与记录行。

**请求方案与实现细节（开发用）**
- 域名选择：
  - 国内：`https://base-api.feishu.cn`
  - 海外：`https://base-api.larksuite.com`
- 认证方式：`Authorization: Bearer {PersonalBaseToken}`。
- Drive 上传：`parent_node` 使用 `app_token`，图片建议 `parent_type=bitable_image`（非图片可用 `bitable_file`）。
- 字段定位：
  - 先调用 `fields` 接口获取 `field_id` 与字段类型，确认目标字段为附件类型（`type=17`）。
  - 若 `field_id` 写入失败，可回退使用字段名，但需确保请求体为 UTF-8。

**记录行映射规则**
- 使用 `records` 接口带 `view_id` 拉取列表，排序规则由视图配置决定。
- “行号”以视图排序后的列表为准，按 1 开始计数。
- 解析 `start_row` 与 `end_row`，校验范围必须在列表长度内。
- 行范围以 `view_id` 视图顺序为准。
- 记录映射：`record_ids = records[start_row - 1 : end_row]`。

**随机上传图片选择规则**
- 读取图片文件夹内可解码图片，生成文件列表。
- 上传数量 `N` 必须满足 `1 <= N <= 可用图片数`。
- 每行随机抽取 N 张，行内不重复，跨行可重复。

**接口调用步骤（建议顺序）**
1. 解析链接：
   - 从 URL 解析 `app_token/table_id/view_id`。
2. 列出字段并确定上传字段：
   - `GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/fields?view_id={view_id}`
   - 找到目标字段名（如“内容页图片”）的 `field_id`，确认 `type=17`。
3. 列出记录并映射行号：
   - `GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records?view_id={view_id}&page_size=200`
   - 处理分页，直到获取足够行。
4. Drive 上传素材：
   - `POST /open-apis/drive/v1/medias/upload_all`
   - 表单字段：`file_name/parent_type/parent_node/size/checksum/extra/file`
   - 多维表格上传点：`parent_node=app_token`
    - `parent_type` 规则（官方文档）：
      - 云空间上传：`explorer`
      - 云文档素材上传：`docx_image` / `docx_file` / `sheet_image` / `bitable_image` / `bitable_file` / `calender`
      - 导入文件：`ccm_import_open`
   - `extra` 规则（官方文档）：
     - 云文档素材上传：`{"drive_route_token":"素材所在云文档的 token"}`
     - 多维表格素材下载：`{"bitablePerm":{"tableId":"...","rev":N}}`
     - 导入文件：`{"obj_type":"docx","file_extension":"md"}`
   - `checksum` 规则（官方文档）：
     - Adler-32 校验和，可选参数。
     - 若传入且校验失败，接口返回错误（如 1062008）。
   - 结果返回 `file_token`。
5. 写入记录：
   - `POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_update`
   - Body 示例（字段名方式）：
     - `{"records":[{"record_id":"recxxx","fields":{"内容页图片":[{"file_token":"xxx"}]}}]}`

**请求体编码注意**
- PowerShell 直接序列化字段名时可能发生编码问题，推荐：
  - 显式 `Content-Type: application/json; charset=utf-8`
  - 或在 JSON 中使用 `\u` 转义字段名。
- 使用 PersonalBaseToken 时，`field_id_type=field_id` 在 `batch_update` 可能返回 `FieldNameNotFound`，可直接用字段名作为字段键。

**批量更新行为说明**
- 附件字段的更新为“覆盖写入”，若需要保留原有附件，需要先读取并合并。

**错误处理（关键场景）**
- Token 失效：接口返回鉴权错误，提示重新授权。
- 字段不存在/非附件类型：提示更换字段或重新配置。
- 行范围超出记录数：提示调整行号/数量。
- Drive 上传失败：提示并跳过本张，记录失败原因。

**接口测试记录（已执行）**

## 8. AI 开发辅助说明
- 目标是 Windows 桌面应用，优先保持现有 `场景化图片排版工具.html` 作为 UI 基础。
- 业务逻辑建议拆分为独立模块，便于 AI 辅助开发与后续扩展：
  - `file-scan`: 递归扫描与过滤文件。
  - `convert-doc`: Word/PPT/PDF 转图片。
  - `image-postprocess`: 放大、裁剪、命名与输出。
  - `feishu-client`: Base/Drive API 调用与鉴权。
  - `upload-random`: 随机抽取与去重策略。
- Office COM 建议串行执行（避免多进程 Office 残留与锁定）。
- PDFium 建议使用稳定绑定库并进行灰度/异常处理，避免大文件崩溃。
- 图片后处理建议使用成熟库（如 `sharp`），保证裁剪与缩放质量一致。
- 任何包含授权码的配置应视为敏感信息，避免写入源码或日志。
- 错误需收集到统一日志（文件+UI 展示），便于排查。

## 12. 验收标准
**文档导出**
- 支持单文件与文件夹递归导出，输出目录可选。
- 文件夹模式保留子目录结构，在对应子目录下输出图片。
- doc/docx/ppt/pptx/pdf 均可生成 PNG，数量与页/幻灯片一致。
- 命名规则符合：`文档名称-页码.png`，冲突时追加 `-ext` 与序号。
- 放大 1.5x/2x 生效；3:4 裁剪输出比例误差不超过 1 像素。
- 无可处理文件/处理失败时有明确错误提示和失败列表。

**随机上传飞书**
- 图片文件夹无图片时提示错误。
- 每行上传数超过文件夹图片总数时提示错误。
- 指定字段必须为附件字段，否则提示错误。
- 每行追加指定数量的随机图片到附件字段。
- 保留原有附件，新图片追加而非覆盖。
- 单个图片上传失败时跳过并继续，不中断整批任务。
- 行内图片不重复，跨行允许重复。

**稳定性与体验**
- 大批量处理不中断（例如 100+ 文档或 1000+ 页）。
- 关键步骤有日志与进度反馈。

## 13. 测试标准与用例
**功能测试（必测）**
- 单文件导出：docx 2 页、pptx 3 页、pdf 2 页。
- 文件夹导出：包含子文件夹与同名文件。
- 放大/裁剪组合测试：无放大、1.5x、2x，裁剪开/关。
- 命名冲突：同名不同扩展或重复导出。

**飞书上传测试**
- 链接解析与字段识别（字段必须为附件类型）。
