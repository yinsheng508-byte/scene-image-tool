# 百变拼图模板复制与菜单改造（修订版开发规划）

> 版本：v1.1  
> 日期：2026-02-24  
> 状态：可实施（仅文档修订，代码未改）

---

## 一、文档评审结论（已修订项）

### 1.1 原规划中不合理或不完整点

1. **复制流程若走 `buildTemplate(name, AppState)` 会覆盖原模板，不是复制**
   - 原因：`buildTemplate` 会优先复用 `currentTemplate.id`。
2. **复制模板 `id` 仅用 `tpl-${Date.now()}` 存在同毫秒冲突概率**
   - 风险低但真实存在，需规避。
3. **模板名缺少兜底**
   - 若原模板名为空会出现 ` - 复制` 这种脏数据。
4. **事件绑定方案建议新加一个全局 `document.click`，会和现有全局点击逻辑重复**
   - 维护成本更高，建议合并到已有全局点击处理。
5. **菜单层级值偏低**
   - `z-index: 200` 虽然多数可用，但和页面其他浮层更容易互相遮挡，建议提高。
6. **“复制对象来源”未明确**
   - 需要明确是“已保存模板快照”还是“当前未保存编辑状态”。

### 1.2 修订后的原则

1. 复制以**当前选中的已保存模板对象**为准（来自 `templates` 数组）。
2. 复制后生成**唯一 id**、**唯一名称**、新时间戳。
3. 菜单交互与预览态禁用行为必须完整闭环。
4. 尽量复用现有重命名弹窗与状态同步链路，不引入重复机制。

## 二、需求确认（最终口径）

### 2.1 模板复制

- 入口：`⋮` 菜单 -> `复制模板`
- 复制内容：原模板完整业务数据（拼图、坑位、裁剪、文字、图片、样式、generationMode）
- 命名规则：
  - 首次：`原模板名 - 复制`
  - 重名：`原模板名 - 复制(2)`、`(3)`...
  - 原名为空时，按 `未命名模板 - 复制` 起名
- 复制完成：
  - 新模板插入列表头部（`unshift`）
  - 当前模板切换为新模板
  - toast：`已复制为「xxx」`

### 2.2 菜单改造

- 原铅笔重命名按钮替换为 `⋮` 按钮。
- 下拉菜单包含：
  - `重命名`（复用 `openTemplateModal("rename")`）
  - `复制模板`（新增逻辑）
- 菜单关闭条件：
  - 再点一次 `⋮`
  - 点击菜单外区域
  - 选择菜单项
  - 进入预览态
  - 当前模板失效/为空
- 禁用规则：
  - `AppState.currentTemplate` 不存在时，`⋮` 按钮 disabled

### 2.3 复制来源口径（关键）

- **复制对象来源：`templates` 数组里的当前模板项**
- 这意味着：
  - 未保存改动不会自动带入复制模板
  - 如需带入最新编辑内容，用户需先点“保存模板”

## 四、详细技术方案

### 4.1 `index.html` 改造

在 `puzzle-tab-actions` 中，把：

```html
<button id="puzzleTemplateRenameBtn" ...>...</button>
```

替换为：

```html
<div class="puzzle-template-menu-wrap" id="puzzleTemplateMenuWrap">
  <button id="puzzleTemplateMenuBtn" type="button" class="puzzle-template-menu-btn"
          title="更多模板操作" aria-label="更多模板操作"
          aria-haspopup="true" aria-expanded="false">
    <!-- 三点竖排图标 -->
  </button>
  <div class="puzzle-template-dropdown" id="puzzleTemplateDropdown" role="menu">
    <button id="puzzleRenameTemplateItem" type="button" class="puzzle-template-dropdown-item" role="menuitem">重命名</button>
    <button id="puzzleDuplicateTemplateItem" type="button" class="puzzle-template-dropdown-item" role="menuitem">复制模板</button>
  </div>
</div>
```

### 4.2 `puzzle.css` 改造

1. 删除 `.puzzle-template-rename` 相关样式。
2. 新增 `.puzzle-template-menu-wrap` / `.puzzle-template-menu-btn` / `.puzzle-template-dropdown` / `.puzzle-template-dropdown-item`。
3. 菜单层级建议：
   - `z-index: 1200`（高于普通面板与自定义下拉，低于全屏 modal）
4. 覆盖 `.puzzle-tabs button:hover` 带来的动画，避免菜单项 hover 抖动（`transform: none; box-shadow: none`）。

### 4.3 `ui-bindings.js` 改造

删除旧字段：

```js
templateRenameBtn
```

新增字段：

```js
templateMenuWrap
templateMenuBtn
templateDropdown
renameTemplateItem
duplicateTemplateItem
```

### 4.4 `template-manager.js` 改造

新增 `duplicateTemplate(template, existingTemplates)`，要求：

1. 输入校验（无模板直接抛错或返回 null，由调用方兜底提示）。
2. 名称去重函数 `buildDuplicateName(base, existingNames)`。
3. 生成唯一 id：
   - 推荐：`tpl-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`
   - 同时可用 `existingIds` 再做一次 while 去重。
4. 返回新模板：
   - `id/name/createdAt/updatedAt` 重建
   - `generationMode` 原值拷贝
   - `puzzles` 深拷贝（可复用本文件 `clone`）

### 4.5 `index.js` 改造

#### 4.5.1 import

```js
import { loadTemplates, saveTemplates, buildTemplate, applyTemplate, duplicateTemplate } from "./template-manager.js";
```

#### 4.5.2 菜单函数

新增：

- `openTemplateDropdown()`
- `closeTemplateDropdown()`
- `toggleTemplateDropdown()`

要求：

- 同步 `aria-expanded`
- 防御空元素

#### 4.5.3 复制函数

新增 `handleDuplicateTemplate()`：

1. 先关菜单。
2. 校验当前模板 id。
3. 从 `templates` 找到 source。
4. `duplicateTemplate(source, templates)` 生成新对象。
5. `templates.unshift(newTemplate)`，调用 `saveTemplates`。
6. 失败时回滚内存插入。
7. 成功后更新：
   - `AppState.currentTemplate`
   - `updateTemplateSelect()`
   - `saveStateToStorage()`
   - toast + log

#### 4.5.4 动作状态函数

更新 `updateTemplateActionState()`：

- 从控制 `templateRenameBtn` 改为控制 `templateMenuBtn`
- 无模板时 disabled 且强制关闭菜单

#### 4.5.5 预览态联动

在 `setPreviewState` 的禁用控件列表里加入 `elements.templateMenuBtn`，并在 `isPreview === true` 时执行 `closeTemplateDropdown()`。

#### 4.5.6 事件绑定

在 `bindEvents()` 中：

1. 移除旧重命名按钮绑定。
2. 增加三点菜单按钮绑定。
3. 菜单项绑定：
   - rename -> `handleRenameTemplate()`
   - duplicate -> `handleDuplicateTemplate()`
4. **不新增第二个全局 click 监听器**，将“点击外部关闭模板菜单”并入已有 `document.addEventListener("click", ...)` 逻辑里统一处理。

#### 4.5.7 额外收口点（建议）

在以下动作后主动关闭模板菜单，防止残留：

- `handleTemplateChange()`
- `handleDeleteTemplate()`
- `closeTemplateModal()`

## 五、风险与边界

### 5.1 数据一致性

- 风险：保存失败导致 UI 与磁盘状态不一致  
- 控制：失败即回滚 `templates` 内存插入

### 5.2 命名与标识冲突

- 风险：同名模板、同 id 模板  
- 控制：名称 while 去重 + id 二次校验去重

### 5.3 交互层级问题

- 风险：菜单被其他组件遮挡  
- 控制：提升菜单层级并验证与 modal、自定义 select 共存

### 5.4 业务口径误解

- 风险：用户期待复制未保存改动  
- 控制：在产品说明与提示中写明“复制的是已保存模板”；若要复制当前编辑结果，先保存模板
