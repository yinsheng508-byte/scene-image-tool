# 百变拼图 - 固定工作区居中缩放与画布外框选开发任务卡

更新时间：2026-08-16

## 一、文档目的

本文档用于把以下两个需求拆成可执行的开发任务：

1. 编辑页和预览页的中间编辑区固定高度，不再被画布尺寸撑高；画布在固定工作区内自适应缩放，并且缩放后始终保持居中。
2. 鼠标起始点不在实际画布内容上时，也可以按住左键拖拽框选坑位、文字、图片等元素。

本文档只做落地规划，不直接修改业务代码。

---

## 二、需求边界

## 2.1 固定工作区与居中缩放

### 目标

- 中间编辑/预览区域高度固定在当前页面可视区域内。
- 画布尺寸再高，也不再撑高页面。
- 左侧编辑面板保持当前视口内独立滚动，方便持续调整属性。
- 编辑模式、预览模式都使用同一套固定工作区布局。
- 任意缩放、切换拼图页、切换预览/编辑、窗口大小变化后，画布显示区域都保持居中。

### 硬约束

- 缩放不能以鼠标位置或旧偏移为锚点。
- 缩放后 wrapper 层必须重新居中。
- 编辑态 `editor.view.offsetX / offsetY` 也必须重新计算为居中值。
- 预览态 `previewView.offsetX / offsetY` 也必须重新计算为居中值。

### 需要明确处理的现有能力

当前 `canvas-editor.js` 支持按住空格拖动画布视图，这会导致画面偏离中心。

本期建议采用“中心锁定”策略：

- 自动缩放、切页、窗口变化、进入/退出预览后强制回正居中。
- 如产品要求“任何时候都必须居中”，则禁用空格拖动画布平移。
- 如仍需保留临时查看平移，则必须定义为用户主动偏移；下一次缩放/适配/切页/预览切换时回正居中。

根据当前用户描述，推荐直接禁用或不再暴露会破坏中心锁定的平移入口。

---

## 2.2 画布外起手框选

### 目标

- 从中间灰色工作区空白区域按下鼠标，也可以拖出选区。
- 选区可以覆盖画布内部的坑位、文字、图片。
- 起始点坐标允许在画布逻辑区域之外。
- 保留现有点击选择、拖动、缩放、旋转、右键菜单、快捷键复制删除等机制。

### 行为建议

- 点中元素：仍按现有图层命中逻辑选择并拖动。
- 点中空白工作区：进入框选。
- 框选时：
  - `Ctrl` / `Shift`：追加选择。
  - `Alt`：套索选择。
  - 无修饰键：替换当前选择。
- 当前无选中对象时，从空白处框选建议同时扫描坑位、文字、图片。
- 当前已有选中类型时，优先框选同类型对象，避免用户想调整文字却误选大量坑位。

## 三、当前实现梳理

## 3.1 页面结构

### `desktop/renderer/index.html`

当前拼图模块结构：

- `.puzzle-layout`
  - `.puzzle-sidebar`
  - `.puzzle-main`
    - `.puzzle-tabs`
    - `#puzzleCanvasWrapper`
      - `#puzzleCanvas`
      - 空状态、预览遮罩、预览控制条、缩放控制、右键菜单
    - `.puzzle-image-list`

关键现状：

- `#puzzleCanvasWrapper` 直接放在 `.puzzle-main` 下。
- 没有独立的固定高度工作区容器。
- 预览工具条和右键菜单都挂在 `#puzzleCanvasWrapper` 内。

## 3.2 布局样式

### `desktop/renderer/puzzle.css`

当前关键样式：

- `.puzzle-body`
  - `height: 100%`
  - `display: flex`
- `.puzzle-layout`
  - `height: 100%`
  - `flex: 1`
- `.puzzle-sidebar`
  - 固定宽度 `280px`
  - `overflow-y: auto`
- `.puzzle-main`
  - `overflow: auto`
  - `padding: 16px`
- `.puzzle-canvas-wrapper`
  - `width: 100%`
  - `aspect-ratio: var(--puzzle-aspect, 3 / 4)`
  - `min-height: 260px`

关键问题：

- `.puzzle-main` 是滚动容器。
- `#puzzleCanvasWrapper` 会按自身宽度和画布比例计算高度。
- 高画布会把 `.puzzle-main` 撑高，最终导致页面纵向滚动。
- 当前缩放是通过调整 wrapper 宽度间接影响高度，不是固定工作区内的显示缩放。

## 3.3 编辑/预览缩放实现

### `desktop/renderer/puzzle/index.js`

当前相关函数：

- `applyEditorContainerZoom(zoomValue)`
- `getEditorBaseScale()`
- `setEditorZoomCentered(nextZoom)`
- `setPreviewScaleCentered(scale)`
- `resizeCanvas()`
- `observeCanvasWrapper()`
- `setPreviewState(isPreview)`

当前逻辑特点：

1. `applyEditorContainerZoom()` 在 `zoom < 1` 时设置 `#puzzleCanvasWrapper.style.width = "xx%"`。
2. `zoom >= 1` 时清空 wrapper 的宽度、高度相关内联样式。
3. `resizeCanvas()` 读取 wrapper 的 `getBoundingClientRect()`，然后设置 canvas 像素尺寸。
4. 编辑态在 `zoom > 1` 且窗口变化时，会尝试保留旧中心世界坐标：
   - 这对“自由视图缩放”是合理的。
   - 但与“缩放画面始终居中”的新要求冲突。
5. 预览态已有 `setPreviewScaleCentered()`，但仍依赖 canvas 当前尺寸，且缺少固定 stage 容器。

结论：

- 需要把缩放模型从“wrapper 宽度驱动”改为“固定 stage 尺寸驱动”。
- 新模型中，wrapper 的 `width/height/left/top` 都由 JS 计算。
- 编辑态和预览态都必须使用居中布局函数。

## 3.4 画布编辑器与选择实现

### `desktop/renderer/puzzle/canvas-editor.js`

当前负责坑位：

- 坑位点击命中
- 坑位拖动
- 坑位缩放
- 坑位框选
- 空格平移
- Ctrl 滚轮缩放入口

当前框选状态：

- `selectionDrag`
- `selectionActive`
- `startWorld`
- `startScreen`
- `mode: "rect" | "lasso"`

问题：

- 事件绑定在 `canvas`。
- 起点必须来自 canvas 事件。
- 鼠标从 canvas 外的灰色工作区按下时，坑位框选不会启动。

### `desktop/renderer/puzzle/text-editor.js`

当前负责文字：

- 文字点击命中
- 文字拖动、缩放、旋转
- 双击编辑
- 文字框选

问题：

- 事件绑定在 `canvas`。
- 没命中文字时存在阻断逻辑：
  - 当前无选中文字且存在坑位时，直接 `return`。
- 这会导致从空白处框选文字的行为受坑位存在与当前选区影响。

### `desktop/renderer/puzzle/image-editor.js`

当前负责图片元素：

- 图片点击命中
- 图片拖动、缩放、旋转
- 图片框选

问题：

- 事件绑定在 `canvas`。
- 没命中图片时存在阻断逻辑：
  - 当前无选中图片且存在坑位时，直接 `return`。
  - 当前无选中图片且存在文字选区时，直接 `return`。

### `desktop/renderer/puzzle/index.js`

当前统一状态：

- `AppState.selectedSlotIds`
- `AppState.selectedTextIds`
- `AppState.selectedImageIds`
- `selectionOverlay`

当前已有能力：

- `drawSelectionOverlay(ctx, overlay)` 可以画框选预览。
- `getElementAtWorldPoint(worldPoint)` 可以做顶层元素命中。
- `getSlotAtWorldPoint(worldPoint)` 可以做坑位命中。

结论：

- 可以复用现有选中状态和渲染能力。
- 但框选入口需要从三个编辑器内部分散逻辑，升级为 stage 级统一选择控制。

## 四、总体技术方案

## 4.1 新增固定工作区 stage

新增 DOM：

```html
<div id="puzzleStage" class="puzzle-stage">
  <div class="puzzle-canvas-wrapper" id="puzzleCanvasWrapper">
    ...
  </div>
</div>
```

职责划分：

- `puzzle-main`：中间列容器，不滚动画布。
- `puzzle-stage`：固定高度工作区，负责容纳并裁剪画布。
- `puzzle-canvas-wrapper`：实际画布显示层，由 JS 设置尺寸和居中位置。
- `canvas`：继续作为绘制载体。

## 4.2 统一居中布局函数

建议新增函数：

- `getPuzzleStageRect()`
- `getActiveCanvasLogicalSize()`
- `getStageFitScale(canvasSize, stageRect)`
- `getCurrentDisplayScale()`
- `layoutCanvasInStage(options)`
- `centerEditorView(scale)`
- `centerPreviewView(scale)`

核心公式：

```javascript
const fitScale = Math.min(stageWidth / canvasWidth, stageHeight / canvasHeight);
const displayScale = fitScale * zoomRatio;
const wrapperWidth = canvasWidth * displayScale;
const wrapperHeight = canvasHeight * displayScale;
const wrapperLeft = (stageWidth - wrapperWidth) / 2;
const wrapperTop = (stageHeight - wrapperHeight) / 2;
```

居中要求：

```javascript
wrapper.style.width = `${wrapperWidth}px`;
wrapper.style.height = `${wrapperHeight}px`;
wrapper.style.left = `${wrapperLeft}px`;
wrapper.style.top = `${wrapperTop}px`;
```

编辑态 view：

```javascript
editor.setView({
  scale: displayScale,
  offsetX: 0,
  offsetY: 0
});
```

说明：

- wrapper 已经承担显示缩放和居中。
- canvas 内部 world 坐标可以直接按 `displayScale` 映射。
- 如果继续让 `canvas.width/height = wrapperWidth/wrapperHeight`，则 `offsetX/offsetY` 可以为 0。
- 如果 canvas 仍保持 stage 尺寸，则需要把 `offsetX/offsetY` 设为居中值。

推荐方式：

- canvas 尺寸跟随 wrapper 尺寸。
- wrapper 自己在 stage 内居中。
- editor/preview view 的 offset 归零或只保留极小校正值。

这样最符合“缩放画面一直居中”的产品要求。

## 4.3 预览态统一走 stage 布局

预览态不再单独依赖 `elements.canvas.width / height` 作为全工作区尺寸。

需要统一：

- 预览任务画布尺寸 `task.canvasSize`
- stage fitScale
- 预览 zoomRatio
- wrapper 显示尺寸
- previewView.scale
- previewView.offsetX / offsetY

建议预览态也使用：

```javascript
previewView = {
  scale: displayScale,
  offsetX: 0,
  offsetY: 0
};
```

如果保留 canvas 等于 stage 大小的模型，则必须：

```javascript
previewView = {
  scale: displayScale,
  offsetX: (canvasWidth - logicalWidth * displayScale) / 2,
  offsetY: (canvasHeight - logicalHeight * displayScale) / 2
};
```

本期推荐选择“canvas 跟随 wrapper，offset 归零”的方案，减少双重居中逻辑。

## 4.4 stage 级统一框选

新增统一选择控制器，建议新建文件：

- `desktop/renderer/puzzle/selection-controller.js`

职责：

- 监听 `puzzleStage` 的 `mousedown`
- 监听 `window` 的 `mousemove/mouseup`
- 判断是否点中已有元素
- 点中元素时让原编辑器处理
- 点中空白或画布外区域时启动统一框选
- 将 screen 坐标转换成 world 坐标
- 计算坑位/文字/图片命中
- 更新 `AppState.selectedSlotIds / selectedTextIds / selectedImageIds`
- 更新 `selectionOverlay`

坐标策略：

```javascript
const canvasRect = canvas.getBoundingClientRect();
const screenPoint = {
  x: event.clientX - canvasRect.left,
  y: event.clientY - canvasRect.top
};
const worldPoint = editor.toWorld(screenPoint);
```

重要点：

- 不要因为 `screenPoint` 在 canvas 外就 return。
- worldPoint 为负数或大于画布尺寸是允许的。

## 八、风险与规避

## 8.1 风险：双重缩放导致坐标错乱

原因：

- wrapper 缩放一层。
- canvas 内部 view 又缩放一层。

规避：

- 明确选择一种模型。
- 推荐：wrapper 负责显示尺寸，canvas 尺寸跟随 wrapper，editor/preview view 的 scale 等于显示 scale，offset 归零。
- 不允许同时出现 wrapper 缩放和 view 额外保留偏移。

## 8.2 风险：文字编辑框位置偏移

原因：

- `textarea` 当前 append 到 `canvasWrapper`。
- wrapper 改为绝对定位后，定位基准变化。

规避：

- 保持 textarea 仍在 wrapper 内。
- `updateTextEditorPosition()` 继续用 editor.view.scale 映射。
- 布局变化后立即调用 `updateTextEditorPosition()`。

## 8.3 风险：右键菜单边界计算错误

原因：

- 当前 `showSlotMenu()` 基于 `canvasWrapper` 边界。
- 新增 stage 后，菜单可能应限制在 stage 或 wrapper 内。

规避：

- 如果菜单挂在 wrapper 内，继续用 wrapper。
- 如果希望画布外右键也能显示菜单，则菜单应迁移到 stage 并按 stage 限制边界。

## 8.4 风险：旧框选逻辑与新 controller 抢事件

原因：

- 三个 editor 当前都监听 canvas mousedown。
- 新 controller 也监听 stage mousedown。

规避：

- 第一阶段只新增 stage 空白框选。
- 第二阶段再逐步移除 editor 内部 selectionDrag。
- 点中元素时让对应 editor 优先处理；点中空白时 controller 接管。

## 8.5 风险：中心锁定与空格平移冲突

原因：

- 空格平移会改变 `editor.view.offsetX / offsetY`。

规避：

- 本期推荐禁用空格平移。
- 或定义下一次缩放/切页/窗口变化强制回正。
