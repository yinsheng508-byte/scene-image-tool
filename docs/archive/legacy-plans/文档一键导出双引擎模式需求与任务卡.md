# 文档一键导出双引擎模式需求、方案与任务卡

> 适用范围：`desktop/` 文档一键导出  
> 文档状态：开发前设计稿  
> 最后审查：2026-07-23  
> 核心原则：保留 LibreOffice 默认免安装能力，新增用户显式选择的 Microsoft Office 高保真能力；一套导出入口、一套进度、一套错误体系，只切换 `Word/PPT -> PDF` 引擎。

---

## 1. 背景

当前产品是面向大量普通用户的服务型桌面工具，不是只给开发者或内部本机使用。大量用户没有安装 WPS 或 Microsoft Office，因此现有 Full 版已经把 LibreOffice 作为内置默认导出引擎，保证用户安装软件后即可导出。

用户反馈的问题集中在复杂文档导出质量：

1. PPT 在 WPS 或 Microsoft Office 中打开正常，但工具导出后文字换行、错位。
2. Word、思维导图类内容导出后出现乱码、排版异常。
3. 同一文件用 WPS/Office 打开正常，用当前工具导出不一致。

根因判断：

```text
Office 文档
  -> 当前工具使用 LibreOffice 解释并转 PDF
  -> LibreOffice 与 WPS / Microsoft Office 的 OOXML 排版引擎不同
  -> 复杂字体、文本框、SmartArt、形状、思维导图、母版样式可能发生差异
  -> PDFium / Sharp 只是后续渲染，不是主要根因
```

所以本次改造不能简单提高 PNG 清晰度，也不能只调 PDF 渲染参数。正确方向是新增一个“本机 Microsoft Office 高保真导出”模式，让对排版一致性要求更高、且电脑已安装 Office 的用户显式选择。

---

## 2. 最终产品口径

文档一键导出只提供两种模式：

```text
LibreOffice（默认，免安装）
Office（本机高保真，需安装 Microsoft Office）
```

明确不做：

1. 不做 `auto` 自动选择。
2. 不把模式选择放到设置页。
3. 不把 WPS 纳入第一版 `Office` 模式。
4. 不接回旧版整套 Office 批量导出流程。
5. 不做 Office 失败后自动回退 LibreOffice。

推荐入口：

```text
文档一键导出
  导出设置
    导出引擎      [ LibreOffice（默认，免安装） v ]
    清晰度倍率    [ 1x v ]
    导出前几页    [ 留空=全部 ]
    输出到子文件夹 [  ]
```

默认规则：

1. 初次打开、存储值缺失、存储值异常时，默认 `LibreOffice`。
2. 可以记忆用户上次在导出页选择的模式，但它只是导出页 UI 状态，不是全局设置页配置。
3. 即使记忆了 `Office`，每次开始导出前仍必须按本批文件严格预检。

## 3. 用户价值与成功标准

### 3.1 用户价值

| 用户类型 | 当前痛点 | 新模式价值 |
|---|---|---|
| 无 Office 用户 | 需要免安装导出 | 继续默认使用 LibreOffice |
| 有 Office 用户 | 复杂 PPT/Word 导出排版不准 | 可切换 Office 高保真导出 |
| 客服/运营 | 用户只说“导出乱”，难以判断环境 | 日志明确展示使用的引擎与失败阶段 |
| 开发维护 | 历史 Office 链路和当前 LO 链路命名混乱 | 统一抽象 `Word/PPT -> PDF` 引擎 |

### 3.2 成功标准

1. 默认路径不回归：未安装 Office 的用户仍可使用 LibreOffice 导出。
2. 高保真路径可用：安装 Microsoft Office 的机器上，Office 模式可导出 Word/PPT。
3. 入口清楚：模式选择在“文档一键导出”的导出设置第一项。
4. 预期清楚：选择 Office 时弹窗说明依赖、风险和检测结果。
5. 诊断清楚：结果里能看到 `engineRequested`、`engineUsed`、`stage`、`errorCode`。
6. 边界清楚：纯 PDF 不应被 Office/LibreOffice 环境预检阻止。

## 4. 当前代码事实

### 4.1 当前 UI

位置：

```text
desktop/renderer/index.html
```

当前“导出设置”第一项是：

```text
清晰度倍率 scaleSelect
```

需要新增：

```text
导出引擎 exportEngineSelect
```

并放在 `scaleSelect` 前面。

### 4.2 当前前端状态

位置：

```text
desktop/renderer/renderer.js
```

当前已有导出相关状态：

```js
selectionState.lastScanItems
storageKeys.exportPageLimit
storageKeys.exportUseSubfolder
restoreExportSettings()
bindExportStorage()
handleConvert()
ensureLibreOfficeReadyBeforeConvert()
```

当前问题：

1. 没有 `exportEngine` 状态。
2. `ensureLibreOfficeReadyBeforeConvert()` 强绑定 LibreOffice。
3. `handleConvert()` payload 没有传 `exportEngine`。
4. 自定义 select 包装在 `createGlobalCustomSelect()`，新增 select 后要注册并支持程序性刷新。

### 4.3 当前 IPC

位置：

```text
desktop/preload.js
desktop/main.js
```

当前暴露：

```js
convertDocuments: ipcRenderer.invoke("convert:documents")
cancelConvert: ipcRenderer.invoke("convert:cancel")
officeHealthCheck: ipcRenderer.invoke("office:healthCheck")
officeHealthFix: ipcRenderer.invoke("office:healthFix")
```

当前问题：

`officeHealthCheck` 名称不准确。它现在实际调用的是 LibreOffice 预检逻辑，不是 Microsoft Office 预检。

### 4.4 当前主进程导出链路

位置：

```text
desktop/main.js
```

当前链路：

```text
convert:documents
  -> runOfficeHealthCheck()        # 实际是 LibreOffice 预检
  -> normalize items
  -> split smallQueue / largeQueue
  -> convertAndRenderOneFile()
  -> convertItem()
  -> PDF 直接渲染
  -> Word 调 runLibreOfficeToPdf()
  -> PPT 调 convertPptSourceToPdf()
  -> PDFium 渲染
  -> Sharp 输出 PNG
```

关键函数：

| 函数 | 当前职责 | 改造判断 |
|---|---|---|
| `runPowerShellScript()` | 执行 PowerShell，当前默认注入 LibreOffice 环境 | 需要支持 Office 脚本跳过 LO env，并可追踪 Office 子进程 |
| `runOfficeHealthCheck()` | 名称是 Office，实际检查 LibreOffice | 必须拆名 |
| `runLibreOfficeToPdf()` | LibreOffice 转 PDF | 保留，包成 LibreOffice adapter |
| `runPptToPdfWithRetry()` | 名称像 PPT 通用转换，实际内部走 LibreOffice | 建议重命名或只作为 LO adapter 内部函数 |
| `convertWordToImages()` | Word -> LO PDF -> 图片 | 需要改为通用引擎 |
| `convertPptToImages()` | PPT -> LO PDF -> 图片 | 需要改为通用引擎 |
| `renderPdfForItem()` | PDF -> 图片共享渲染 | 应作为新链路复用点 |
| `batchConvertToPdf()` | 旧批量转换辅助 | 当前主链路未直接调用，不建议第一版接回 |
| `convert:cancel` | 只终止 LibreOffice pid | 需要同时处理 Office PowerShell / COM |

### 4.5 当前脚本资产

位置：

```text
desktop/scripts/
```

| 脚本 | 当前状态 | 处理 |
|---|---|---|
| `ppt-to-pdf.ps1` | 已有结构化 JSON 输出，调用 `PowerPoint.Application` COM | 可作为 Office PPT 单文件 adapter 基础 |
| `word-to-pdf.ps1` | 只 `Write-Error`，无 JSON 协议 | 必须升级 |
| `office-health-check.ps1` | 偏 PowerPoint、偏 Office16 默认路径 | 不能原样作为最终 Office 预检 |
| `office-health-fix.ps1` | Office 治理脚本 | 第一版不主动修复，只检测提示 |
| `ppt-batch-to-pdf.ps1` | 批量 COM 转换 | 第一版不接 |
| `word-batch-to-pdf.ps1` | 批量 COM 转换 | 第一版不接 |
| `libreoffice-health-check.ps1` | 当前 LO 预检脚本 | 保留并改名接入新 IPC |

## 5. 需求文档

### R1. 导出引擎选择

入口位置：

1. 页面：文档一键导出。
2. 区块：导出设置。
3. 顺序：第一个配置项，位于清晰度倍率前。
4. 控件：下拉选择。

选项：

```text
LibreOffice（默认，免安装）
Office（本机高保真，需安装 Microsoft Office）
```

字段：

```js
exportEngine: "libreoffice" | "office"
```

验收：

1. 初次打开默认为 LibreOffice。
2. 选择 Office 后控件显示 Office。
3. 开始导出 payload 包含 `exportEngine`。
4. 设置页不出现该配置。

### R2. Office 模式说明弹窗

触发时机：

```text
用户从 LibreOffice 切换到 Office
```

弹窗内容：

```text
Office 高保真导出

该模式会调用本机 Microsoft Office 转 PDF，排版更接近 Office 打开效果。
需要当前电脑已安装并可正常启动 Word / PowerPoint。
导出可能比 LibreOffice 更慢，且可能受 Office 激活、登录弹窗、插件影响。

检测结果
Word        可用 / 不可用 / 未检测
PowerPoint  可用 / 不可用 / 未检测

[继续使用 Office] [切回 LibreOffice] [重新检测] [复制诊断]
```

交互规则：

1. 弹窗是说明和轻量检测，不等于最终导出许可。
2. 如果此时已经扫描到文件，则按本批文件展示“本次需要 Word / PowerPoint”。
3. 如果尚未扫描文件，则可检测 Word 和 PowerPoint 的 COM 注册状态，或者展示“未选择文件，开始导出前会再次检测”。
4. 点击“继续使用 Office”：保留 Office。
5. 点击“切回 LibreOffice”：select 恢复 LibreOffice，并刷新自定义 select 文案。
6. 点击遮罩或关闭按钮：按“切回 LibreOffice”处理，避免用户误选。
7. 点击“重新检测”：重新调用轻量检测。
8. 点击“复制诊断”：复制可读诊断文本。

### R3. 开始导出前严格预检

点击“开始导出”后，先根据当前扫描结果计算 requiredApps。

| 批次内容 | requiredApps | 预检规则 |
|---|---|---|
| 仅 PDF | `[]` | 不需要 Office/LibreOffice 预检 |
| DOC/DOCX | `["word"]` | Office 模式要求 Word 可用 |
| PPT/PPTX | `["powerpoint"]` | Office 模式要求 PowerPoint 可用 |
| Word + PPT | `["word", "powerpoint"]` | Office 模式要求二者都可用 |
| Word/PPT + PDF | 按 Word/PPT 计算 | PDF 不额外增加要求 |

LibreOffice 模式：

1. 只要批次里存在 Word/PPT，就执行 LibreOffice 预检。
2. 纯 PDF 不执行 LibreOffice 阻断式预检。

Office 模式：

1. 只要批次里存在 Word/PPT，就执行 Microsoft Office 预检。
2. 缺少 requiredApps 时阻止整个批次开始，提示用户切回 LibreOffice。
3. 第一版不自动导出 PDF 子集，也不自动跳过失败类型，避免结果和用户预期不一致。

### R4. 导出行为

行为原则：

1. PDF 文件始终走现有 PDFium 渲染，不受引擎选择影响。
2. Word/PPT 文件的第一阶段转 PDF 按用户选择切换引擎。
3. 转成 PDF 后，图片渲染、输出命名、页数限制、输出到子文件夹、进度统计全部复用现有逻辑。

目标链路：

```text
convert:documents
  -> normalizeExportEngine(payload.exportEngine)
  -> normalizeItems
  -> computeRequiredApps(items)
  -> precheck only when needed
  -> queue
  -> convertAndRenderOneFile
      -> PDF: renderPdfForItem(source)
      -> Word/PPT:
          -> convertOfficeSourceToPdf(engine)
          -> renderPdfForItem(pdf)
  -> diagnostics
```

### R5. Office 模式并发

Office COM 模式必须稳定优先。

规则：

1. 如果 `exportEngine=office` 且批次包含 Word/PPT，则 Office 文档转 PDF 必须串行。
2. 第一版建议直接将包含 Office 文档的文件级并发降为 1。
3. 纯 PDF 批次不受 Office 串行限制。
4. 不复用 `ppt-batch-to-pdf.ps1` / `word-batch-to-pdf.ps1`。

原因：

Microsoft Office COM 受激活弹窗、插件、受保护视图、RPC busy、全局模板、默认打印机等因素影响，并发启动多个 Word/PowerPoint 实例更容易卡死或互相干扰。

### R6. 取消与超时

用户点击取消时：

```text
conversionAbortRequested = true
terminateActiveLibreOfficeProcesses()
terminateActiveOfficeProcesses()
```

约束：

1. 只能清理本任务启动或能合理归属本任务的进程。
2. 禁止无条件杀 `WINWORD.EXE` 或 `POWERPNT.EXE`，避免关闭用户自己打开的文档。
3. PowerShell 超时后应返回结构化错误，包含 `scriptName`、`timeoutMs`、`durationMs`。
4. Office 脚本 finally 中必须执行 `Close()`、`Quit()`、`ReleaseComObject()`、GC。

### R7. 诊断日志

导出开始日志必须包含：

```text
exportEngine=libreoffice
```

或：

```text
exportEngine=office
```

单文件转换结果必须包含：

```js
conversionMeta: {
  engineRequested: "office",
  engineUsed: "office",
  stage: "ppt_to_pdf",
  openMode: "open",
  repaired: false,
  attempts: 1,
  retries: 0,
  workerRebuilds: 0,
  durationMs: 1234,
  timeoutMs: 180000,
  fallbackReason: "",
  errorCode: "",
  envWarning: ""
}
```

诊断对象建议：

```js
diagnostics: {
  exportEngine: {
    requested: "office",
    effective: "office",
    requiredApps: ["word", "powerpoint"],
    precheckSkipped: false,
    precheckReason: ""
  },
  libreoffice: {},
  office: {},
  ppt: {},
  word: {}
}
```

## 6. 技术方案

### 6.1 前端改造

新增 DOM：

```js
const exportEngineSelect = document.getElementById("exportEngineSelect");
```

新增 storage key：

```js
exportEngine: "exportEngine"
```

新增函数：

```js
function normalizeExportEngine(value) {}
function getSelectedExportEngine() {}
function setSelectedExportEngine(engine, options = {}) {}
function computeRequiredOfficeApps(items) {}
async function ensureExportEngineReadyBeforeConvert(engine, items) {}
async function openOfficeEngineModal(report, context = {}) {}
```

`handleConvert()` 调整：

```text
validate output folder
validate scan items
validate pageLimit
engine = getSelectedExportEngine()
ready = await ensureExportEngineReadyBeforeConvert(engine, selectionState.lastScanItems)
if !ready return
payload.exportEngine = engine
convertDocuments(payload)
```

需要注意：

1. 新 select 也要注册 `createGlobalCustomSelect()`。
2. 程序性切回 LibreOffice 时，需要刷新 custom select 实例。
3. `latestLibreOfficeDiagnosticsText` 应扩展为通用 `latestExportDiagnosticsText`，或新增 `latestOfficeDiagnosticsText`。

### 6.2 preload 改造

新增：

```js
exportHealthCheck: (payload) => ipcRenderer.invoke("export:healthCheck", payload || {})
```

保留兼容：

```js
officeHealthCheck
officeHealthFix
```

新前端不再直接调用 `officeHealthCheck`。

### 6.3 主进程预检改造

新增：

```js
function normalizeExportEngine(value) {}
function computeRequiredOfficeApps(items) {}
async function runLibreOfficeHealthCheck(options = {}) {}
async function runMicrosoftOfficeHealthCheck(options = {}) {}
async function runExportEngineHealthCheck(options = {}) {}
```

新增 IPC：

```js
ipcMain.handle("export:healthCheck", async (_event, payload) => {})
```

接口入参：

```js
{
  engine: "libreoffice" | "office",
  requiredApps: ["word", "powerpoint"],
  timeoutMs: 20000,
  refreshRuntime: true,
  light: true
}
```

接口出参：

```js
{
  ok: true,
  result: {
    engine: "office",
    blockExport: false,
    score: 90,
    requiredApps: ["word"],
    apps: {
      word: { required: true, ok: true, method: "com_registry", detail: "" },
      powerpoint: { required: false, ok: false, method: "", detail: "" }
    },
    checks: [],
    warnings: [],
    suggestions: [],
    actions: [],
    raw: {}
  }
}
```

LibreOffice 预检迁移：

1. 将当前 `runOfficeHealthCheck()` 拆成 `runLibreOfficeHealthCheck()`。
2. 旧 `office:healthCheck` 可以暂时转调 `runLibreOfficeHealthCheck()`，避免其他历史调用断裂。
3. 新代码使用 `export:healthCheck`。

Office 预检要求：

1. 不依赖 `Office16` 默认路径作为唯一判断。
2. 使用 COM ProgID / 注册表检测：
   - `Word.Application`
   - `PowerPoint.Application`
3. 轻量检测不要主动打开真实文档。
4. requiredApps 缺失时 `blockExport=true`。
5. 激活、登录、插件卡死等运行期问题不能完全靠预检查出，由转换阶段错误承接。

### 6.4 转 PDF 引擎抽象

新增统一入口：

```js
async function convertOfficeSourceToPdf(item, pdfPath, options = {}) {
  const engine = normalizeExportEngine(options.exportEngine);
  if (engine === "office") {
    return convertWithMicrosoftOffice(item, pdfPath, options);
  }
  return convertWithLibreOffice(item, pdfPath, options);
}
```

LibreOffice adapter：

```js
async function convertWithLibreOffice(item, pdfPath, options = {}) {}
```

Office adapter：

```js
async function convertWithMicrosoftOffice(item, pdfPath, options = {}) {}
```

统一返回：

```js
{
  ok: true,
  pdfPath,
  engineRequested: "office",
  engineUsed: "office",
  stage: "word_to_pdf",
  openMode: "open",
  repaired: false,
  attempts: 1,
  retries: 0,
  durationMs: 0,
  timeoutMs: 0,
  fallbackReason: "",
  errorCode: "",
  envWarning: "",
  raw: {}
}
```

改造方向：

1. `convertWordToImages()` 和 `convertPptToImages()` 不再直接知道 LO 或 Office 细节。
2. 它们只负责：
   - 建临时目录
   - 调 `convertOfficeSourceToPdf()`
   - 调 `renderPdfForItem()` 或 `convertPdfFileToImages()`
   - 返回 `conversionMeta`
3. Word 也必须返回 `conversionMeta`，当前 Word 链路没有这一层，需要补齐。

### 6.5 Office 单文件脚本协议

PPT 使用：

```text
desktop/scripts/ppt-to-pdf.ps1
```

Word 使用：

```text
desktop/scripts/word-to-pdf.ps1
```

Word 脚本必须升级为 JSON 输出：

```json
{
  "ok": true,
  "message": "Word 转 PDF 完成",
  "error": "",
  "rawError": "",
  "errorCode": "",
  "openMode": "open",
  "repaired": false,
  "fallbackReason": "",
  "envWarning": "",
  "durationMs": 1234,
  "retries": 0
}
```

失败时：

```json
{
  "ok": false,
  "message": "Word 转 PDF 失败",
  "error": "...",
  "rawError": "...",
  "errorCode": "0x800a....",
  "openMode": "",
  "repaired": false,
  "fallbackReason": "open_failed",
  "envWarning": "",
  "durationMs": 1234,
  "retries": 0
}
```

脚本要求：

1. 输出必须 UTF-8 JSON。
2. 最后一行必须是完整 JSON，方便 `parsePowerShellJsonOutput()` 解析。
3. 失败时仍输出 JSON，然后 `exit 1`。
4. 读取文档尽量使用只读模式。
5. 尽量 `Unblock-File -ErrorAction SilentlyContinue`。
6. finally 中关闭文档、退出应用、释放 COM。

### 6.6 PowerShell 执行器调整

当前 `runPowerShellScript()` 默认构造 LibreOffice spawn env。Office 脚本不应该继承这个行为。

建议新增选项：

```js
{
  useLibreOfficeEnv: false,
  trackAs: "office"
}
```

规则：

1. LibreOffice 相关脚本保持 `useLibreOfficeEnv !== false`。
2. Office COM 脚本传 `useLibreOfficeEnv: false`。
3. `trackAs: "office"` 时记录 PowerShell pid 到 `activeOfficePids`。
4. 关闭、失败、超时后从 set 移除。

### 6.7 队列策略

当前队列：

```text
normalizedItems
  -> runnableTasks
  -> smallQueue 按文件大小排序
  -> largeQueue 按原顺序
  -> smallQueue 并发
  -> largeQueue 串行
```

Office 模式建议：

```js
const hasOfficeConvertibleFiles = normalizedItems.some((item) => isOfficeConvertibleExt(item.ext));
const effectiveSmallQueueConcurrency =
  exportEngine === "office" && hasOfficeConvertibleFiles
    ? 1
    : smallQueueConcurrency;
```

验收口径：

1. `exportEngine=libreoffice`：维持现有并发策略。
2. `exportEngine=office` 且包含 Word/PPT：文件级串行，日志明确 `smallQueueConcurrency=1 reason=office_com_serial`。
3. `exportEngine=office` 但仅 PDF：不强制 Office 预检，可沿用现有 PDF 渲染并发策略。

### 6.8 大文件策略

当前 `convertAndRenderLargeOfficeTask()` 失败后会调用 `terminateActiveLibreOfficeProcesses()`，这是 LO 时代逻辑。

改造要求：

1. 如果 `exportEngine=libreoffice`，继续清理 LibreOffice。
2. 如果 `exportEngine=office`，清理 Office PowerShell / 本任务 Office COM。
3. 大文件重试仍可保留，但 Office 模式第一版建议 `largeFileMaxAttempts` 不放大，避免重复打开同一超大文档造成更长卡顿。
4. `conversionMeta.workerRebuilds` 在 Office 模式下要避免误导，可以保留字段但日志写成 `attempts/retries`。

### 6.9 LibreOffice 字体基线

这是独立但重要的问题。

当前 `desktop/package.json` 的 `extraResources` 中包含：

```text
program/**
share/**
presets/**
System/**
System64/**
...
```

但没有明确包含：

```text
Fonts/**
```

如果 `vendor/libreoffice/Fonts` 中存在可分发字体，打包后不可见会放大中文换行、乱码、文本框溢出等问题。

建议拆成独立任务，不阻塞双引擎第一版：

```text
LibreOffice 字体基线优化
  -> 打包包含可分发 CJK 字体
  -> 启动时确认 LO 可见字体
  -> 增加字体替换/缺失诊断
  -> 用真实问题样本做回归
```

## 9. 推荐实施顺序

```text
阶段 0：提交文档/版本基线
阶段 1：前端 UI + exportEngine payload
阶段 2：预检 IPC 拆分，先保持 LibreOffice 默认链路不变
阶段 3：抽象 Word/PPT -> PDF，并让 LibreOffice 走新 adapter
阶段 4：升级 Word 脚本，接回 Office 单文件 adapter
阶段 5：Office 串行、取消、超时治理
阶段 6：Office 弹窗和严格预检联调
阶段 7：诊断日志、测试、打包
阶段 8：独立处理 LibreOffice 字体基线
```

这样做的原因：

1. 先保证默认 LibreOffice 通过新抽象跑通，降低主路径回归风险。
2. 再接 Office adapter，避免两套流程同时变化。
3. 最后处理 UI 弹窗和诊断，让真实返回结构稳定后再完善呈现。
