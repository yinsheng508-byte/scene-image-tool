# 百变拼图模块 — 多文件夹模式改造方案

## 一、改造概述

本次改造包含两部分：
1. **删除**「封面+内页循环」模式（无用功能清理）
2. **新增**「多文件夹模式」（一个拼图模板对应一个文件夹，独立生成）

改造后生成规则变为两种互斥模式：
- **单一文件夹循环**（single）：现有行为不变，所有图片共享
- **多文件夹模式**（multi-folder）：每个拼图页绑定独立文件夹

## 四、新增「多文件夹模式」

### 4.1 数据模型变更

#### AppState 新增字段

```javascript
// state.js
export const AppState = {
  // ... 现有字段不变
  generationMode: "single",     // 改为 "single" | "multi-folder"
  folderBindings: {},            // 新增：多文件夹绑定状态
};
```

#### folderBindings 结构

```javascript
// 键为 puzzle.id，值为绑定信息
folderBindings = {
  "puzzle-1234": {
    folder: "D:\\photos\\产品A",
    images: [
      { id: "img-xxx-0", name: "01.jpg", path: "D:\\photos\\产品A\\01.jpg" },
      { id: "img-xxx-1", name: "02.jpg", path: "D:\\photos\\产品A\\02.jpg" }
    ]
  },
  "puzzle-5678": {
    folder: "D:\\photos\\产品B",
    images: [...]
  }
  // 未绑定的 puzzle 不在此对象中，或值为 null
}
```

#### 设计决策

**folderBindings 独立于 puzzle 对象**，原因：
- puzzle 对象会被模板序列化保存，文件夹绑定是**运行时状态**，不应随模板持久化
- 与 `AppState.images` 同级管理，职责清晰
- **模板加载时主动清空 folderBindings**，避免旧绑定错配到新模板

**folderBindings 跟随 puzzle.id**，不跟随序号：
- 新增/删除/排序 puzzle tab 不会导致绑定错乱
- 删除 puzzle 时同步清理 `delete folderBindings[deletedPuzzle.id]`

### 4.3 弹窗交互流程

```
用户点击「选择文件夹」按钮
        ↓
弹出自定义弹窗，列出所有拼图页
        ↓
┌─────────────────────────────────────────────────┐
│  拼图1    产品A (10张)              [选择] [清除] │
│  拼图2    未选择文件夹               [选择]        │
│  拼图3    产品B (5张)               [选择] [清除] │
└─────────────────────────────────────────────────┘
                                [取消]  [确认]
        ↓
用户点击某行的「选择」
        ↓
弹出系统原生文件夹选择对话框（复用 dialog:openFolder）
        ↓
选择文件夹后自动调用 scanPuzzleImages 扫描图片
        ↓
弹窗中即时更新该行显示（文件夹名 + 图片数量）
        ↓
用户点击「确认」→ 保存绑定到 AppState.folderBindings
用户点击「取消」→ 丢弃本次编辑
```

**关键细节：**
- 弹窗打开时，将 `AppState.folderBindings` 深拷贝为 `tempFolderBindings` 作为临时编辑缓冲
- 弹窗内所有操作修改的是 `tempFolderBindings`
- 确认时才将 `tempFolderBindings` 写回 `AppState.folderBindings`
- 取消时丢弃 `tempFolderBindings`，不影响已有绑定
- **扫描失败**：提示错误并保持原绑定不变（或清空本次选择）

### 4.5 生成引擎改造

#### generation-engine.js

```javascript
export function buildTaskQueue(puzzles, images, mode, folderBindings) {
  if (!Array.isArray(puzzles) || puzzles.length === 0) return [];

  if (mode === "multi-folder") {
    return buildMultiFolderQueue(puzzles, folderBindings || {});
  }

  // single 模式：保持现有 buildSingleQueue 不变
  if (!Array.isArray(images) || images.length === 0) return [];
  return buildSingleQueue(puzzles, images);
}
```

#### buildMultiFolderQueue 核心算法

```javascript
function buildMultiFolderQueue(puzzles, folderBindings) {
  const tasks = [];
  let outputIndex = 1;

  for (const puzzle of puzzles) {
    const binding = folderBindings[puzzle.id];
    // 无绑定、无图片、无坑位 → 跳过
    if (!binding?.images?.length || !puzzle.slots?.length) continue;

    const images = binding.images;
    let imageIndex = 0;

    while (imageIndex < images.length) {
      const slots = [];
      const beforeIndex = imageIndex;
      for (const slot of puzzle.slots) {
        if (imageIndex >= images.length) {
          slots.push(cloneSlot(slot, null));
          continue;
        }
        slots.push(cloneSlot(slot, images[imageIndex].path));
        imageIndex += 1;
      }
      if (imageIndex === beforeIndex) break;
      tasks.push(buildTask(puzzle, slots, outputIndex));
      outputIndex += 1;
    }
  }

  return tasks;
}
```

**生成顺序**：Puzzle A 全部 → Puzzle B 全部 → ...（全局递增序号）

#### calculateEstimateCount 适配

```javascript
export function calculateEstimateCount(puzzles, images, mode, folderBindings) {
  return buildTaskQueue(puzzles, images, mode, folderBindings).length;
}
```

## 六、边界场景处理

| 场景 | 处理方式 |
|------|----------|
| 多文件夹模式下所有 puzzle 均未绑定文件夹 | 图片列表显示所有 puzzle 为"未选择"，预计生成 0 张，预览/生成时提示"没有可生成的内容" |
| 多文件夹模式下 puzzle 有文件夹但文件夹内无图片 | 该 puzzle 显示"0张"，不生成 |
| 多文件夹模式下 puzzle 无 slot（坑位） | 即使绑定了文件夹也跳过不生成 |
| 切换回 single 模式 | `folderBindings` 保留不清除（下次切回仍可用），展示 `AppState.images` |
| 加载模板 | 模板不含 folderBindings，绑定状态清空；generationMode 从模板恢复 |
| 旧版本数据 `generationMode === "cover-inner"` | 自动降级为 `"single"` |
| 新增 puzzle tab | 新 puzzle 无绑定，弹窗中显示"未选择"，不生成 |
| 删除 puzzle tab | 同步 `delete folderBindings[puzzle.id]` |
| 文件夹路径失效（已删除/移动） | 下次打开弹窗时路径照常显示，但选择后扫描将报错或返回 0 张；不做主动校验 |
