## 目标

新增一套飞书上传模式：

```text
选择一个父文件夹，或添加多个入口文件夹
  ↓
递归扫描入口文件夹
  ↓
最下层子文件夹 = 一篇笔记
  ↓
按入口顺序优先、入口内部自然排序生成笔记列表
  ↓
从起始行开始逐行上传到飞书附件字段
```

必须保留当前「分模块上传」全部行为：

- 多文件夹配置
- 顺序上传
- 随机上传
- 每行数量
- 多文件夹合并写入
- 取消上传
- 飞书字段校验与错误翻译

## 关键验收场景

## 场景 1：入口顺序优先

输入：

```text
入口:
  1. 账号B
  2. 账号A

账号B:
  1-家居
  2-家居

账号A:
  1-穿搭
  10-家居
```

预期：

```text
账号B / 1-家居 -> 第 2 行
账号B / 2-家居 -> 第 3 行
账号A / 1-穿搭 -> 第 4 行
账号A / 10-家居 -> 第 5 行
```

## 场景 2：追加入口影响行号

操作：

```text
先添加账号B，再追加账号A
```

预期：

```text
账号B 的笔记先写入
账号A 的笔记后写入
```

## 场景 3：删除笔记后重排

删除前：

```text
A -> 第 2 行
B -> 第 3 行
C -> 第 4 行
```

删除 B 后：

```text
A -> 第 2 行
C -> 第 3 行
```

## 场景 4：重新扫描恢复删除

操作：

```text
删除 B
点击重新扫描
```

预期：

```text
B 恢复，行号恢复为连续映射
```

## 场景 5：入口根部图片

目录：

```text
入口A
├─ root.png
└─ 笔记1
   └─ 01.png
```

预期：

```text
入口A 有子目录，root.png 不上传
笔记1 作为笔记
```

目录：

```text
入口B
├─ 01.png
└─ 02.png
```

预期：

```text
入口B 无子目录且有图片，入口B 本身作为 1 篇笔记
```

## 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 多选目录在 Windows 文件选择器体验不稳定 | 影响添加多个入口 | 实测 `openDirectory + multiSelections`，必要时退化为多次添加 |
| 递归扫描大目录耗时 | UI 等待时间长 | 扫描时显示状态，避免重复点击 |
| 入口包含关系导致重复笔记 | 重复上传 | 按完整路径去重，保留靠前入口结果 |
| 删除笔记后用户误以为删除本地文件 | 误解 | UI 文案明确“仅从待上传列表移除” |
| 重复执行追加附件 | 附件重复 | 上传前提示默认追加，覆盖模式后续再做 |
| 拆分 `uploadImages` 引入旧模式回归 | 影响现有用户 | 先迁移旧逻辑为 `handleFeishuModuleUpload`，保留 payload 兼容 |
