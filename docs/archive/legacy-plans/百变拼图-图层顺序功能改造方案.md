# 百变拼图 - 图层顺序功能改造方案（完整版）

## 1. 背景与目标

用户需求：

1. 百变拼图中，`坑位`、`文字`、`图片元素`均支持图层顺序调整。
2. 右键菜单增加并同时支持：`移至顶层`、`移至底层`。
3. 编辑态、预览态、导出结果保持一致。

本方案仅为开发规划文档，不直接修改业务代码。

### 2.2 当前渲染分层（固定）

当前编辑态渲染顺序：

1. 背景（纯色或背景图）
2. 坑位层（`drawSlots(...)`）
3. 文字 + 图片元素层（按 `createdAt` 混排）
4. 选中框/控制点/UI 覆盖层

结论：现有架构下，`坑位`整体在`文字/图片元素`下方；本期不改变这一大分层。

### 2.3 当前命中与排序机制

- 坑位命中：按 `puzzle.slots` 倒序命中（数组末尾优先）。
- 文字/图片命中：主入口 `getElementAtWorldPoint` 按 `createdAt` 排序后倒序命中。
- 文字编辑器内部命中（`text-editor.js`）当前仍按 `puzzle.texts` 数组顺序倒序查找，不完全跟随 `createdAt`，这是潜在不一致点。

### 2.4 当前右键菜单

- 菜单容器：`#puzzleSlotMenu`
- 现有按钮：复制、删除
- 上下文类型：`contextMenuTarget = "slot" | "text" | "image"`

## 3. 方案总览（本期推荐）

### 3.1 分层策略

采用“分层内调序、分层间不跨越”的方案：

- 坑位：在坑位层内部调整顺序（通过 `puzzle.slots` 重排）。
- 文字/图片：在元素层内部调整顺序（通过 `createdAt` 调整）。
- 坑位与文字/图片之间：保持当前大分层，不支持互相跨层。

该方案满足本期业务需求，改造范围可控，兼容现有导出与预览链路。

### 3.2 菜单策略

右键菜单对三种类型统一展示 4 个操作：

1. 复制
2. 删除
3. 移至顶层
4. 移至底层

复制/删除文案仍按类型动态变更；图层操作文案固定。

### 3.3 多选策略

与当前复制/删除行为保持一致：若右键点击对象已在当前选区内，则图层操作作用于“当前选中集合”。

## 4.3 主流程改造（index.js）

### 文件

- `desktop/renderer/puzzle/index.js`

### 改造点 A：右键菜单动作扩展

新增两个处理函数并注册事件：

- `handleSlotMenuBringToFront()`
- `handleSlotMenuSendToBack()`

行为：

1. 校验菜单可见和编辑模式。
2. `pushUndoState()`。
3. 根据 `contextMenuTarget` 调用对应调序逻辑。
4. 更新属性面板、持久化、重绘。
5. `hideSlotMenu()`。

### 改造点 B：坑位调序逻辑（数组重排）

新增辅助函数：

- `bringSlotsToFront(selectedSlotIds)`
- `sendSlotsToBack(selectedSlotIds)`

算法要求：

1. 支持多选。
2. 保持多选对象内部相对顺序稳定。
3. 仅重排 `puzzle.slots`，不改坑位几何与样式字段。

示例伪代码：

```js
const selectedSet = new Set(selectedIds);
const selected = slots.filter((s) => selectedSet.has(s.id));
const rest = slots.filter((s) => !selectedSet.has(s.id));

// 置顶
slots = [...rest, ...selected];

// 置底
slots = [...selected, ...rest];
```

### 改造点 C：文字/图片调序逻辑（createdAt 调整）

新增辅助函数：

- `bringElementsToFront(targetType, selectedIds)` // targetType: `text` 或 `image`
- `sendElementsToBack(targetType, selectedIds)`
- `normalizeElementCreatedAt(puzzle)` // 推荐加入

核心规则：

1. 文字和图片共享一个元素层级序列（混排）。
2. 置顶：目标集合放到元素序列末尾（视觉最上）。
3. 置底：目标集合放到元素序列开头（视觉最下）。
4. 调整后执行一次 `createdAt` 归一化，避免时间戳无限增减。

推荐归一化策略：

```js
const elements = [...texts, ...images]
  .sort((a, b) => (a.createdAt || 0) - (b.createdAt || 0));

let seed = Date.now();
elements.forEach((el, i) => {
  el.createdAt = seed + i;
});
```

### 改造点 D：菜单文案更新

`updateSlotMenuLabels()` 保留现有“复制/删除”按类型切换逻辑，并确保新增两个图层按钮始终可用（无需按类型隐藏）。

### 改造点 E：一致性修复（命中行为）

为确保“调层后点击命中结果”与视觉一致，需要补充：

1. `text-editor.js` 的 `findTextAtPoint(...)` 改为按 `createdAt` 排序后倒序命中。
2. 若 `index.js` 内存在仅按数组顺序命中的文字辅助函数，也应同步按 `createdAt`。

## 5. 关键算法细节

## 5.1 右键作用对象判定

延续现有逻辑：

1. 命中对象若未选中，先切换成单选。
2. 命中对象若已在选区，保留选区不变。
3. 图层操作作用于当前选区（对应类型）。

## 5.2 稳定排序原则

无论置顶还是置底，均需保持被操作对象之间原有相对顺序不变，避免视觉跳变。

## 5.3 createdAt 漂移控制

每次图层调整后做一次轻量归一化，避免连续操作后出现过大/过小值引发潜在排序边界问题。

## 8. 风险与规避

## 8.1 风险：文字命中与视觉顺序不一致

原因：文本编辑器内部命中若仍按数组顺序。

规避：`text-editor.js` 统一按 `createdAt` 命中。

## 8.2 风险：createdAt 绝对值漂移

原因：长期 `+1/-1`。

规避：每次调序后归一化。

## 8.3 风险：多选操作顺序错乱

原因：直接逐个移动而非稳定分组。

规避：使用“selected + rest”稳定拼接算法。
