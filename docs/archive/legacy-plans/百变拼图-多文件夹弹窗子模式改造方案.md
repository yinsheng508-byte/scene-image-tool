# 百变拼图 — 多文件夹弹窗子模式改造方案（方案A落地版）

## 一、文档目的

本文档基于现有百变拼图代码实现，明确采用 **方案A**：

- **外层生成模式保持不变**：`单一文件夹循环` / `多文件夹模式`
- **仅在“多文件夹模式”的“选择文件夹”弹窗内新增子模式**
- 保留现有“逐个指定拼图”能力
- 新增“子文件夹模式”作为默认子模式

本文档重点补齐以下内容：

- 与现有代码一致的真实行为定义
- 可以直接实现的状态结构
- 前后端任务流与 IPC 设计
- 模板工作区持久化规则
- 输出目录与命名规则

---

## 二、结论先行

### 2.1 最终产品形态

外层仍然只有两种生成模式：

| 外层模式 | 说明 |
|------|------|
| `单一文件夹循环` | 现有行为，不变 |
| `多文件夹模式` | 打开“选择文件夹”弹窗后，再选择子模式 |

多文件夹模式的弹窗内新增两个子模式：

| 子模式 | 标识 | 说明 |
|------|------|------|
| `子文件夹模式` | `subfolder-batch` | 选择 1 个父文件夹，按其第一层子文件夹批量生成 |
| `逐个指定拼图` | `per-puzzle-folder` | 现有行为：每个拼图页绑定 1 个文件夹 |

### 2.2 核心设计原则

1. **不推翻现有多文件夹模式**
   现有 `逐个指定拼图` 保持原实现路径不变。

2. **子文件夹模式复用“单一文件夹循环”的任务构建逻辑**
   每个子文件夹都按当前真实的单文件夹规则独立生成，不使用简化公式硬算。

3. **新增独立状态分支，不把两种子模式硬塞进同一个 `folderBindings` 语义里**
   现有 `folderBindings` 只继续服务 `per-puzzle-folder`。

4. **模板文件仍然不保存运行时文件夹绑定**
   子模式、父路径、扫描结果、逐拼图绑定等都只写入工作区状态，不写入模板文件本体。

## 三、现有代码事实

本方案以下列现状为前提。

### 3.1 当前多文件夹模式的真实语义

当前 `multi-folder` 并不是“选择一个父目录按子目录批处理”，而是：

- 每个拼图页绑定一个文件夹
- 每个拼图页使用自己的图片池生成
- 可选“支持多张拼图共享循环同一文件夹”

对应代码：

- `AppState.folderBindings`：`desktop/renderer/puzzle/state.js`
- `buildMultiFolderQueue()`：`desktop/renderer/puzzle/generation-engine.js`
- 文件夹弹窗：`desktop/renderer/puzzle/index.js`

### 3.2 当前单文件夹模式的真实生成逻辑

当前单文件夹模式并不是简单的：

```text
ceil(图片数 / 所有坑位总数)
```

而是：

- 先按拼图页顺序轮转
- 每个拼图页再按坑位填充顺序消费图片
- 若开启“拼图1作为封面（仅生成1张）”，则首张单独由拼图1生成，后续只轮转剩余拼图页

因此：

> 子文件夹模式如果要求“完全沿用当前单文件夹规则”，就必须复用现有单文件夹任务构建逻辑，而不是重新写一套简化公式。

## 四、最终需求定义

## 4.1 外层模式

外层模式不变：

- `single`
- `multi-folder`

### 4.2 多文件夹模式的弹窗子模式

`multi-folder` 下新增子模式字段：

- `subfolder-batch`
- `per-puzzle-folder`

默认值：

- 新工作区默认 `subfolder-batch`
- 恢复工作区时恢复上次子模式

### 4.3 子模式职责边界

#### `subfolder-batch`

- 用户选择一个父文件夹
- 只扫描父文件夹第一层子文件夹
- 每个子文件夹只扫描其第一层图片
- 每个子文件夹独立按“当前单文件夹规则”生成
- 所有子文件夹结果顺序拼接

#### `per-puzzle-folder`

- 保持现有实现
- 每个拼图页绑定一个文件夹
- 继续支持“多张拼图共享循环同一文件夹”

## 五、状态模型

## 5.1 推荐新增状态结构

在 `AppState` 中新增统一配置对象：

```javascript
AppState = {
  // 现有字段
  generationMode: "single",
  images: [],
  folderBindings: {}, // 兼容保留，继续给 per-puzzle-folder 使用
  shareSameFolderCycleInMultiFolder: true,
  outputByPuzzleFolder: true,
  singleFirstPuzzleOnce: false,

  // 新增
  multiFolderConfig: {
    subMode: "subfolder-batch",
    perPuzzle: {
      folderBindings: {},
      outputByPuzzleFolder: true,
      shareSameFolderCycle: true
    },
    subfolderBatch: {
      parentFolder: "",
      parentFolderAccessible: true,
      groups: [],
      outputByInputSubfolder: true,
      lastScannedAt: 0
    }
  }
}
```

### 5.2 子文件夹模式数据结构

```javascript
subfolderBatch: {
  parentFolder: "D:\\照片\\产品图库",
  parentFolderAccessible: true,
  groups: [
    {
      key: "商品A",
      name: "商品A",
      folderPath: "D:\\照片\\产品图库\\商品A",
      images: [
        { id: "img-1", name: "001.jpg", path: "D:\\照片\\产品图库\\商品A\\001.jpg" }
      ],
      imageCount: 12
    }
  ],
  outputByInputSubfolder: true,
  lastScannedAt: 1713438200000
}
```

说明：

- `groups` 必须保存扫描结果，不能只保存路径
- `parentFolderAccessible` 用于恢复弹窗时展示“路径不可访问”
- `key` 默认可直接等于子文件夹名；若未来需要防重，可改为 `folderPath`

### 5.3 兼容策略

为减少改动范围，短期内保留：

- `AppState.folderBindings`
- `AppState.outputByPuzzleFolder`
- `AppState.shareSameFolderCycleInMultiFolder`

但约定如下：

- `per-puzzle-folder` 继续读写旧字段
- `multiFolderConfig.perPuzzle` 作为未来的标准结构
- 本次实现允许在状态同步层做双写，降低改造成本

## 七、弹窗交互规则

## 7.1 打开弹窗

打开时：

- 从当前工作区恢复上次子模式
- 恢复两种子模式各自独立状态
- 进入草稿态编辑，不直接写回正式状态

建议新增弹窗草稿对象：

```javascript
tempMultiFolderDraft = {
  subMode,
  perPuzzle: { ... },
  subfolderBatch: { ... }
}
```

### 7.2 切换子模式

切换时：

- 不自动确认
- 不丢失另一子模式的草稿状态
- 只切换当前弹窗内容

### 7.3 子文件夹模式选择文件夹

流程：

1. 点击 `选择文件夹`
2. 调用系统文件夹选择
3. 选择后立即调用新的 IPC 扫描
4. 扫描成功则更新草稿中的：
   - `parentFolder`
   - `parentFolderAccessible = true`
   - `groups`
   - `lastScannedAt`
5. 扫描失败则：
   - 更新路径
   - 标记为不可确认
   - 保留错误提示

### 7.4 子文件夹模式再次选择文件夹

不提供单独的 `重新扫描` 按钮。

若用户需要刷新父目录下的子文件夹和图片数据：

- 直接再次点击 `选择文件夹`
- 重新选择同一个父文件夹即可
- 选择成功后重新调用扫描 IPC，并覆盖当前草稿中的扫描结果

### 7.5 确认

确认时：

- 将当前草稿整体写回正式状态
- 刷新左侧图片列表
- 刷新预计生成张数
- 关闭弹窗

### 7.6 取消

取消时：

- 丢弃整个草稿
- 不影响正式状态

## 九、预计生成张数定义

## 9.1 关键原则

**不使用简化公式作为正式规则。**

正式规则为：

> 子文件夹模式下，每个子文件夹都单独调用“现有单一文件夹循环”的任务构建逻辑，最终总张数为所有子文件夹任务数之和。

### 9.2 计算方式

伪代码：

```javascript
let total = 0;

for (const group of groups) {
  const groupTasks = buildSingleQueue(
    puzzles,
    group.images,
    {
      singleFirstPuzzleOnce: AppState.singleFirstPuzzleOnce
    }
  );
  total += groupTasks.length;
}
```

### 9.3 拼图1作为封面

在 `subfolder-batch` 下：

- 该开关 **继续生效**
- 该开关 **继续可见且可编辑**
- 行为是：**每个子文件夹各自独立执行一次封面规则**

即：

- 商品A 批次会有自己的封面图
- 商品B 批次也会有自己的封面图

### 9.4 显示规则

`singleFirstPuzzleOnce` 的 UI 显示规则调整为：

| 外层模式 | 子模式 | 是否显示 |
|------|------|------|
| `single` | - | 显示 |
| `multi-folder` | `subfolder-batch` | 显示 |
| `multi-folder` | `per-puzzle-folder` | 隐藏 |

## 十一、任务构建设计

## 11.1 任务入口改造

`buildTaskQueue()` 增加对子模式分发：

```javascript
buildTaskQueue(puzzles, images, generationMode, folderBindings, options, multiFolderConfig)
```

逻辑：

```javascript
if (generationMode !== "multi-folder") {
  return buildSingleQueue(...);
}

if (multiFolderConfig.subMode === "subfolder-batch") {
  return buildSubfolderBatchQueue(...);
}

return buildMultiFolderQueue(...); // 现有 per-puzzle-folder 逻辑
```

## 11.2 子文件夹模式任务构建

新增：

- `buildSubfolderBatchQueue()`

伪代码：

```javascript
function buildSubfolderBatchQueue(puzzles, groups, options) {
  const tasks = [];
  let outputIndex = 1;

  for (const group of groups) {
    const images = Array.isArray(group.images) ? group.images : [];
    if (!images.length) continue;

    const groupTasks = buildSingleQueue(puzzles, images, {
      singleFirstPuzzleOnce: options.singleFirstPuzzleOnce
    });

    groupTasks.forEach((task, index) => {
      tasks.push({
        ...task,
        outputIndex,
        sourceGroupName: group.name,
        sourceGroupPath: group.folderPath,
        sourceGroupIndex: index + 1
      });
      outputIndex += 1;
    });
  }

  return tasks;
}
```

### 11.3 为什么必须给任务加来源元数据

因为主进程导出时需要知道：

- 这张图属于哪个输入子文件夹
- 应该输出到哪个子目录
- 该子目录内部编号应累计到几

因此子文件夹模式任务必须新增：

- `sourceGroupName`
- `sourceGroupPath`

## 十二、主进程 IPC 设计

## 12.1 不复用现有 `puzzle:scanImages`

原因：

当前 `puzzle:scanImages` 会递归扫描整个目录，不符合新需求。

现有行为：

- 扫描整个目录树
- 返回相对路径名称

新需求：

- 父目录只扫第一层子目录
- 每个子目录只扫第一层图片
- 忽略更深层级

因此必须新增专用 IPC。

## 12.2 新增 IPC

新增：

- `puzzle:scanSubfolderGroups`

入参：

```javascript
{
  parentFolder: "D:\\照片\\产品图库"
}
```

返回：

```javascript
{
  ok: true,
  parentFolder: "D:\\照片\\产品图库",
  parentFolderAccessible: true,
  groups: [
    {
      name: "商品A",
      folderPath: "D:\\照片\\产品图库\\商品A",
      images: [
        { name: "001.jpg", path: "D:\\照片\\产品图库\\商品A\\001.jpg" }
      ]
    }
  ],
  subfolderCount: 3,
  imageCount: 28
}
```

### 12.3 扫描规则

1. 父目录不存在或不可访问：
   - `ok: false`
   - 返回错误信息

2. 父目录第一层仅识别目录项为子文件夹

3. 每个子文件夹仅扫描其第一层图片文件

4. 排序规则：
   - 子文件夹按自然排序
   - 图片按自然排序

5. 空子文件夹：
   - 保留在 `groups` 中
   - `images` 为空数组

## 十三、主进程导出逻辑改造

## 13.1 当前问题

当前主进程导出按 `puzzleName` 建目录，仅适用于逐个指定拼图模式。

子文件夹模式下必须改为：

- 按输入子文件夹建目录
- 按输入子文件夹独立计数

## 13.2 新增导出识别逻辑

生成 payload 增加：

```javascript
{
  generationMode: "multi-folder",
  multiFolderSubMode: "subfolder-batch",
  outputByPuzzleFolder: false,
  tasks: [...]
}
```

主进程分支建议：

```javascript
const isSubfolderBatch =
  payload?.generationMode === "multi-folder"
  && payload?.multiFolderSubMode === "subfolder-batch";
```

### 13.3 子文件夹模式输出到子目录

若：

- `isSubfolderBatch === true`
- `outputByPuzzleFolder === true`

则：

- 使用 `task.sourceGroupName` 建目录
- 每个 `sourceGroupName` 独立计数
- 文件名格式：`模板名_{序号}.png`

### 13.4 子文件夹模式输出平铺

若：

- `isSubfolderBatch === true`
- `outputByPuzzleFolder === false`

则：

- 沿用当前全局计数逻辑
- 文件名格式：`模板名_{全局序号}.png`

### 13.5 逐个指定拼图模式

保留当前逻辑：

- 勾选输出到子文件夹时按拼图页名分目录

## 十四、模板与工作区持久化

## 14.1 模板文件

模板文件本体仍然只保存：

- 拼图结构
- 背景
- 坑位
- 文字
- 图片元素
- `generationMode`
- `singleFirstPuzzleOnce`

**不保存：**

- 父文件夹路径
- 子文件夹扫描结果
- 逐拼图绑定文件夹
- 子模式

## 14.2 工作区状态

以下内容写入工作区状态：

- `generationMode`
- `multiFolderConfig.subMode`
- `perPuzzle.folderBindings`
- `perPuzzle.outputByPuzzleFolder`
- `perPuzzle.shareSameFolderCycle`
- `subfolderBatch.parentFolder`
- `subfolderBatch.parentFolderAccessible`
- `subfolderBatch.groups`
- `subfolderBatch.outputByInputSubfolder`
- `singleFirstPuzzleOnce`

## 14.3 模板切换行为

与现有 `templateWorkingSets` 机制保持一致：

- 同一模板切回来时，恢复该模板的工作区状态
- 不写入模板文件本体

## 14.4 恢复行为细化

恢复 `subfolder-batch` 时：

- 显示上次父路径
- 显示上次扫描结果
- 不自动重新扫描
- 若重新打开弹窗时发现路径不可访问，则显示 `路径不可访问`

实现建议：

- 弹窗打开时，可使用一次轻量 `fs.access` 校验父路径是否可访问
- 不重新扫描目录内容

| 场景 | 处理方式 |
|------|------|
| 父目录下无子文件夹 | 显示红字提示，确认按钮置灰 |
| 子文件夹存在但全部为空 | 可确认，预计生成 0 张，生成时报“没有可生成的内容” |
| 某个子文件夹无图片 | 保留分组，不生成 |
| 子文件夹内有嵌套子文件夹 | 忽略更深层，只扫第一层图片 |
| 父路径失效 | 弹窗显示“路径不可访问”，确认按钮置灰 |
| 切到逐个指定再切回子文件夹 | 保留子文件夹模式草稿/正式状态 |
| 切换模板 | 恢复该模板对应工作区的子模式和扫描结果 |
| 单文件夹切到多文件夹 | 不影响 `AppState.images`，只是当前 UI 隐藏 |
| 多文件夹切回单文件夹 | 不清空多文件夹状态，便于切回后继续使用 |

## 十九、最终拍板口径

本次改造的唯一正式口径如下：

1. 外层 `多文件夹模式` 保留。
2. 弹窗内新增两个子模式：`子文件夹模式`、`逐个指定拼图`。
3. `逐个指定拼图` 完全保留现有行为。
4. `子文件夹模式` 的生成规则不是简化公式，而是“每个子文件夹独立复用当前单一文件夹循环逻辑”。
5. 子文件夹模式继续支持 `拼图1作为封面（仅生成1张）`。
6. 子文件夹模式必须新增专用扫描 IPC，不能直接复用当前递归扫描接口。
7. 子文件夹模式导出时必须按输入子文件夹元数据分目录与计数。
