# 导出实现方案说明（Word / PPT / PDF -> 图片）

## 总体流程
- 输入支持：Word、PPT、PDF
- 输出：每个文件独立文件夹（文件名为目录名），图片按页导出为 PNG
- 流程统一：Word / PPT / PDF -> PDF -> PNG
- 清晰度：目标像素尺寸优先（短边像素）
- 体积控制：已关闭（质量优先）

## Word 导出方案
实现路径
- Word -> PDF：使用 COM `ExportAsFixedFormat` 输出 PDF（打印质量）
- PDF -> PNG：用 PDFium 渲染 + sharp 处理

优点
- 版式一致性高：PDF 固定版式，可精准还原分页、字体、行距
- 清晰度可控：通过 DPI 渲染保证文字清晰
- 稳定性高：Office 官方支持的固定格式输出

缺点
- 需要安装 Office（COM 依赖）
- 中文路径/文件名在某些环境下可能导致 COM 打开失败
- 增加一次中间文件转换（速度略慢）

## PPT 导出方案
实现路径
- PPT -> PDF：使用 PowerPoint COM `ExportAsFixedFormat` 输出 PDF（打印质量）
- PDF -> PNG：用 PDFium 渲染 + sharp 处理

优点
- 版式与文字渲染统一，清晰度更稳定
- 避免 PPT 直接导图的窗口隐藏异常
- 与 Word/PDF 走同一链路，维护成本更低

缺点
- 依赖 Office COM（WPS 兼容性不确定）
- 需要额外的 PDF 中间文件（速度略慢）

## PDF 导出方案
实现路径
- PDFium 渲染页面为高 DPI 位图
- sharp 进行裁剪与 PNG 无损编码（不限制体积）

优点
- 渲染质量高，文字清晰
- 可精确控制 DPI 与输出尺寸
- 支持大批量文档批处理

缺点
- 高 DPI 时 CPU/内存开销较高
- 大页 PDF 渲染时间较长

## 统一清晰度策略
- 目标像素尺寸（短边）：
  - 1x：约 2500px
  - 1.5x：约 3300px
  - 2x：约 4000px
  - 3x：约 4800px
- 渲染顺序：高质量渲染 → 裁剪 → PNG 无损编码

## 当前方案优点汇总
- 清晰度高，倍率越大越清晰
- 版式稳定，可还原 Word/PDF 排版
- 输出结构清晰，每个文件独立目录
- 体积不限制，优先保证清晰度
 - PPT/Word/PDF 统一流程，维护成本低

## 当前方案主要弊端
- 依赖 Office COM（环境要求高）
- 高分辨率下性能压力较大（已加像素上限缓解）
- 中文路径可能导致 COM 打开失败（需规避或自动复制到安全路径）
