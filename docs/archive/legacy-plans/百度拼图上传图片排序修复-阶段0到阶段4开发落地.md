# 百度拼图上传图片排序修复（阶段0-阶段4）

更新时间：2026-03-04

## 阶段0：需求冻结（已完成）

- 排序目标：图片列表按文件名自然排序（`1, 2, 3, 10`），不再使用纯字符串字典序（`1, 10, 11, 2`）。
- 适用范围：
  - 单文件导入（拼图模块“导入图片”按钮）。
  - 文件夹扫描导入（拼图模块多文件夹模式）。
- 稳定性要求：
  - 同名文件时以路径做二级排序，避免列表顺序抖动。
- 兼容要求：
  - 不自动重排历史已保存列表，避免影响用户手动拖拽后的顺序。

## 阶段1：统一排序策略（已完成）

### 前端（Renderer）

- 文件：`desktop/renderer/puzzle/index.js`
- 新增统一比较器：
  - `compareImageNameNatural(left, right)`
  - `compareImageListItemNatural(a, b)`
- 规则：`localeCompare("zh-CN", { numeric: true, sensitivity: "base" })` + 路径兜底。

### 后端（Main）

- 文件：`desktop/main.js`
- 新增统一比较器：
  - `compareNaturalText(left, right)`
  - `comparePuzzleImageEntryNatural(a, b)`
  - `compareImageFilePathNatural(a, b)`
- 与前端使用同一自然排序语义，消除前后端规则不一致。

## 阶段2：前端单文件导入改造（已完成）

- 文件：`desktop/renderer/puzzle/index.js`
- 改造点：`handleImportImages()`
  - 由 `normalized.sort((a, b) => ...localeCompare(...))`
  - 改为 `normalized.sort(compareImageListItemNatural)`
- 保持 `existing.concat(additions)` 策略不变：
  - 只保证“本次新增”内部自然排序。
  - 不打乱已有列表顺序（兼容手动拖拽）。

## 阶段3：后端文件夹扫描改造（已完成）

- 文件：`desktop/main.js`
- 改造点1：`ipcMain.handle("puzzle:scanImages")`
  - 由 `images.sort((a, b) => a.name.localeCompare(...))`
  - 改为 `images.sort(comparePuzzleImageEntryNatural)`
- 改造点2：`getImageFilesSorted(folderPath)`
  - 改为复用 `images.sort(compareImageFilePathNatural)`
  - 保持与扫描接口一致的自然排序规则。

## 阶段4：一致性与兼容策略（已完成）

- 生成链路不改动：
  - 继续按 `AppState.images` / `binding.images` 当前顺序消费，保证“列表即生成顺序”。
- 状态恢复不改动：
  - 未在 `loadStateFromStorage` 增加自动重排逻辑，避免历史模板顺序突变。
- 用户行为兼容：
  - 拖拽重排后，顺序仍以用户操作为准。

## 验收清单（建议执行）

- 用例1：单文件导入 `pptx-1.png ... pptx-12.png`
  - 预期：`1,2,3,...,10,11,12`。
- 用例2：多文件夹扫描导入同名序列
  - 预期：列表自然排序，与单文件导入一致。
- 用例3：存在同名不同路径文件
  - 预期：顺序稳定，不随机跳动。
- 用例4：手动拖拽重排后保存并重开
  - 预期：保持用户手工顺序，不被自动重排覆盖。

## 回滚方案

- 最小回滚点：
  - `desktop/renderer/puzzle/index.js`（导入排序替换）。
  - `desktop/main.js`（扫描排序替换、排序函数复用）。
- 回滚影响：
  - 仅恢复旧字典序，其他拼图功能不受影响。
