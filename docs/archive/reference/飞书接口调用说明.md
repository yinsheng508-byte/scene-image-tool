# 飞书多维表格（Base）接口调用说明（PersonalBaseToken 版本）

本文整理了项目中已验证的飞书 Base/Drive 接口调用方式与关键参数，供后续开发复用。
适用场景：使用 PersonalBaseToken 调用 Base 相关接口，并上传图片到多维表格附件字段。

## 1. 鉴权与域名

- 鉴权：`Authorization: Bearer {PersonalBaseToken}`
- Base/Drive 域名（国内/海外）：
  - `https://base-api.feishu.cn`
  - `https://base-api.larksuite.com`

注意：使用 PersonalBaseToken 在 `https://open.feishu.cn` 会返回鉴权错误（Invalid access token）。

配置方式（项目约定）：
- 使用“多维表格授权码（PersonalBaseToken）+ 多维表格链接”作为输入。
- 系统从链接解析 `app_token/table_id/view_id`，用于后续接口调用。

Base OpenAPI 说明（官方口径）：
- 多维表格在新域名独立部署 Base OpenAPI，接口路径与飞书开放平台一致，仅域名不同。
- 授权码仅可操作 Base 相关开放接口。
- 云文档能力范围：
  - 多维表格（Base）：全部接口
  - 云空间（Drive）：上传素材、下载素材两个接口

## 2. 关键参数获取

从多维表格链接解析：
- `app_token`：`/base/{app_token}` 中的 `{app_token}`
- `table_id`：URL Query 参数 `table`
- `view_id`：URL Query 参数 `view`
注意：若链接路径为 `/wiki/`，`app_token` 需用“开发工具”插件获取。

示例链接（仅示意）：
```
https://xxx.feishu.cn/base/{app_token}?table={table_id}&view={view_id}
```

字段定位：
- 调用 `fields` 接口获取 `field_id`、`field_name` 和 `type`
- 附件字段类型：`type = 17`

## 3. 接口列表与要点

### 3.1 列出字段

```
GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/fields?view_id={view_id}
```

用于确认字段是否存在且为附件类型。
可选参数：`page_size/page_token/text_field_as_array/view_id`。

### 3.2 列出记录（按视图顺序）

```
GET /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records?view_id={view_id}&page_size=200
```

- 记录顺序以 `view_id` 视图顺序为准
- 行号 = 返回 items 的顺序（从 1 开始）
- 常用 Query 参数示例：
  - `filter: CurrentValue.[多行文本]=\"双向关联测试\"`
  - `sort: [\"字段1 DESC\"]`
  - `page_size: 20`
- 响应关键字段：`code/data.items/record_id/page_token/has_more`

响应示例（节选）：
```json
{
  "code": 0,
  "data": {
    "has_more": true,
    "items": [
      { "fields": { "字段A": "xxx" }, "record_id": "rec0iAsbhD" }
    ],
    "page_token": "rec0iAsbhD"
  },
  "msg": "success"
}
```

### 3.3 上传素材（图片/文件）

```
POST /open-apis/drive/v1/medias/upload_all
```

**关键点（已验证）：**
- `parent_node` 必须传 **app_token**
- `parent_type` 推荐：
  - 图片：`bitable_image`
  - 其他文件：`bitable_file`

表单字段（必填）：
- `file_name`
- `parent_type`
- `parent_node`
- `size`
- `file`

说明：`extra` 在该场景不是必填，实际使用 `parent_node=app_token` 可成功返回 `file_token`。
官方示例多使用 `https://open.feishu.cn` + tenant/user access token；在 PersonalBaseToken 场景需改用 `base-api` 域名。

### 3.4 批量更新记录（写入附件）

```
POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_update?ignore_consistency_check=true
```

**关键点（已验证）：**
- 使用 PersonalBaseToken 时，`field_id_type=field_id` 可能返回 `FieldNameNotFound`
- 推荐 **直接使用字段名作为 fields 的 key**

示例 Body（字段名方式）：
```json
{
  "records": [
    {
      "record_id": "recxxx",
      "fields": {
        "内容页图片": [
          { "file_token": "xxx" }
        ]
      }
    }
  ]
}
```

如需保留原有附件：
1) 先通过 `records` 接口读取当前行的字段值
2) 将旧附件与新 `file_token` 合并后再写回

### 3.5 批量新增记录（batch_create）

```
POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_create?ignore_consistency_check=true
```

- Body 以 `records` 数组提交，`fields` 内填写各字段值。
- 示例（字段名方式）：
```json
{
  "records": [
    { "fields": { "文本": "文本内容" } },
    { "fields": { "文本": "文本内容2" } }
  ]
}
```

### 3.6 批量获取记录（batch_get）

```
POST /open-apis/bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_get
```

- Body 示例：
```json
{
  "automatic_fields": true,
  "record_ids": ["recxxx", "recyyy"],
  "with_shared_url": true
}
```

### 3.7 下载素材（download）

```
GET /open-apis/drive/v1/medias/{file_token}/download
```

用途：下载云文档中的素材（图片/附件）。支持在请求头添加 `Range` 进行分片下载。

前提条件：
- 调用身份具备素材下载权限，否则返回 403。
- 仅支持云文档素材下载；云空间资源请用“下载文件”接口。

请求头：
- `Authorization: Bearer {token}`
- 可选：`Range: bytes=start-end`

路径参数：
- `file_token`：素材 token
  - 多维表格场景可从记录附件字段的 `file_token` 获取。

查询参数：
- `extra`：如为“高级权限”多维表格，需按官方说明添加扩展鉴权参数。

cURL 示例：
```bash
curl -i -X GET 'https://base-api.feishu.cn/open-apis/drive/v1/medias/{file_token}/download' -o "{local_file}" \
-H 'Authorization: Bearer {PersonalBaseToken}'
```

响应：
- HTTP 200：返回文件二进制流
- HTTP 206：返回 Range 指定的部分内容

常见状态码：
- 400：高级权限表格未附带 `extra`
- 403：无下载权限
- 404：`file_token` 不存在或已删除
- 500：服务端异常

## 4. 推荐调用流程（附件上传）

1. 解析链接得到 `app_token/table_id/view_id`
2. `fields`：确认目标字段存在且 `type=17`
3. `records`：按视图顺序获取记录，映射行号到 `record_id`
4. `upload_all`：上传图片，取 `file_token`
5. `batch_update`：用字段名写入附件（如需保留原附件先合并）

## 5. 常见错误与排查

- `Invalid access token`：域名用错（open 域名不支持 PersonalBaseToken）
- `Bad Request`：upload_all 参数不全，常见是缺失 `parent_node` 或值错误
- `FieldNameNotFound`：`batch_update` 使用 `field_id_type=field_id` 时触发，改为字段名写入

## 6. upload_all 示例（PersonalBaseToken + base-api）

```bash
curl --location --request POST 'https://base-api.feishu.cn/open-apis/drive/v1/medias/upload_all' \
--header 'Authorization: Bearer {PersonalBaseToken}' \
--form 'file_name="demo.png"' \
--form 'parent_type="bitable_image"' \
--form 'parent_node="{app_token}"' \
--form 'size="1024"' \
--form 'file=@"/path/demo.png"'
```

## 7. 备注

- 图片大小限制：单文件 <= 20MB（超过需分片上传）
- 接口频控：详见官方文档的 QPS/日限额说明
- 字段名写入需保证 UTF-8 编码
